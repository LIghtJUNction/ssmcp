使用指南 · ssmcp {{version}}

从一次连接，
开始本机工作。

ssmcp 把支持 MCP 的 AI 应用连接到你的电脑。MCP 是调用工具的协议：应用发出请求，本机执行命令或处理文件，结果沿连接返回。

连接本身不启动模型。终端里的指南二维码只包含公开网址，不包含登录凭据。

开始 / 01

三步完成第一次连接

  1. 安装客户端

    在需要连接的电脑上选择对应命令。也可以从 GitHub Releases 手动下载。

    Linux / macOS
    curl -fsSL https://github.com/LIghtJUNction/ssmcp/releases/latest/download/install.sh | sh
    Windows PowerShell
    irm https://github.com/LIghtJUNction/ssmcp/releases/latest/download/install.ps1 | iex

    安装后运行 ssmcp --version。能看到客户端版本，再继续下一步。

  2. 在项目目录里连接

    在要处理的文件夹中打开终端，把 yourname 换成自己的服务器用户名，然后运行：

    ssmcp yourname@{{gateway_authority}}

    设备无需登录。可用 ssmcp yourname@{{gateway_authority}} --register 在浏览器注册新用户名。

    保持这个终端运行。以后可以直接运行 ssmcp 复用已保存的连接配置；需要查看账户时，打开账户门户。

  3. 把中继添加到 AI 应用

    在应用的 MCP 连接设置中填写下面的地址，并授权同一个 GitHub 账户。

    {{gateway_origin}}/mcp

    例如在 ChatGPT Plugins 中选择 Add，填写 Name 与 Connection，按界面提示完成 Create 和授权。

    回到对话，让 AI 列出在线客户端，核对电脑与工作目录后再开始任务。列表为空时，先看连接排查。

开始 / 02

连接另一台设备

由被控设备的用户在愿意开放的项目目录中主动运行客户端。把 yourname 换成控制者在同一中继上已注册的用户名。被控端无需登录账号，也无需服务器邀请码。控制者仍须登录自己的服务器账户，MCP 应用须完成该中继的 OAuth 授权。

ssmcp yourname@{{gateway_authority}} --register

下次直接运行 ssmcp 即可复用最近一次成功连接。结束客户端进程即可关闭设备连接。

账户、设备和协作成员有什么区别？

服务器账户决定谁能连接设备；客户端代表一台正在连接的电脑。会话内的协作成员由 collab.join 登记，用于消息与任务协作，不会替代设备授权。

主窗口中的 /invite 生成会话内工作组协作说明。设备访问仍由该连接的允许名单和现有权限检查决定。允许名单不接受裸用户名、@github 或其他服务器的账户。流量按实际控制账户计费，一个账户的额度或权限变化不会断开其他获准控制者。

日常使用 / 01

写需求，带上必要上下文

普通输入按 Enter 后进入当前选定的消息路线。工作继续时可以写下一条草稿；AI 需要继续调用工具，才能有机会接收排队的输入。

输入作用
@src/main.rs引用工作区文件。带空格的路径写成 @"文档/使用 说明.md"。找不到文件时会提示，字面消息仍可发送。
@assets/chart.png让 Agent 实际读取图片。原生读图支持 PNG、JPEG、GIF、WebP，每张图片上限 400 KiB。
$skill-name引用项目或用户技能，附上来源、元数据和读取信息；使用前需读取完整技能，引用本身不会自动执行技能。输入前缀后用 Tab 或 Enter 接受候选，再按 Enter 发送。
!git status --short在当前工作区运行本地 Shell 命令，显示输出与退出状态。
/sessions · /message选择收件人并确认；Esc 返回，保留草稿。
/queue · /copy查看排队请求，或复制最新一条完整的 Agent 回复。
F1 · F7打开帮助，或暂停终端鼠标捕获，用终端自己的方式选择文字。

上表中的 / 命令输入在 SSMCP 聊天框中，不是系统终端的子命令。/paste 导入剪贴板，/attach PATH 附加图片；超过 8 KiB 的粘贴会保存成文件引用，后面仍可补充需求。

消息发送与引用：什么时候附带本机文件？

普通本地请求和本地监听目标的 /send 会准备 @ / $ 引用。原生成员或群组目标的 /send 发送字面正文，禁用引用补全，不会隐式附带本机文件或技能。

queued、included、acknowledged 是递送过程中的回执，不代表对方已经阅读或完成任务。请看实际回复与任务结果。

技术说明 · Worker

主窗口协作，worker 池分工

在项目目录的交互终端启动主聊天和关联的 worker 监控窗口。默认 worker 是外部 Agent，使用它自己的应用和模型；SSMCP 提供队列、工具和回执，不启动模型。

ssmcp yourname@{{gateway_authority}} --worker 3

三个席位初始都是离线。主窗口保留聊天输入；worker 窗口显示任务状态和日志。启动时需要可用的终端适配器来打开第二个窗口。

主窗口命令作用
/invite生成主协调者的接入说明
/invite worker生成指向关联池的外部 worker 说明
/worker ls查看席位、注册、工作中、待命与离线数量
/worker +2增加两个离线席位；尚无池时创建关联窗口
/worker -1请求减少一个席位，等待任务完成与退役确认

在已连接的主窗口输入 /invite 并按 Enter，把说明粘贴到已获准接入的主 Agent 对话；主 Agent 在控制会话以 main 加入并绑定自己的凭据。邀请外部 worker 前，用 /worker ls 确认关联池在线且有空位，再输入 /invite worker 并按 Enter，把说明交给每个独立、已获准接入的 worker 对话。

两个邀请命令都会打开可滚动面板并尝试复制；剪贴板不可用时手动复制，按 Esc 关闭。各 Agent 私下保管自己的凭据；池满员、离线或正在调整席位时，先等待状态恢复。

把说明交给对应的 Agent。外部 worker 在池连接中用 collab.join 登记 role: "worker"，绑定自己的私有凭据，再调用 ssmcp.worker.wait 注册席位并等候任务。registered_workers 计注册人数，working 计执行中的任务，standby／idle 才是待命容量；创建席位或复制邀请不代表已有 worker 接入。

协调者在池中完成管理者绑定后，用 ssmcp.worker.submit 派发任务。Worker 保留完整 claim，用 ssmcp.worker.complete 报告实际结果，再换新请求 ID 等待；等待重试复用原 ID。取消要等执行者确认，断线造成的 unknown 不自动重放。窗口退出、重载和缩容的完整行为见 Worker 指南。

按真实事件等待

Code Mode 回复末尾的提示词 hook 读取真实关联池状态，并检查调用者的绑定、协调角色和权限。它以有节流、长度有界的建议提示分工；独立工作完成后，建议等待 user.input_available、worker.completed、worker.idle 和 worker.progress。建议不会自动执行任务或启动模型。

events.policy 可调整当前成员的 enabled、window_ms、kinds 和 strategy；后者是建议文本。使用已经取得的控制会话 ID 和该连接自己的凭据：

修改等待建议
await collab.bind(controlId, controlCredentials);
return await events.policy(controlId, {
  patch: {
    enabled: true,
    window_ms: 55000,
    kinds: ["user.input_available", "worker.completed", "worker.idle", "worker.progress"],
    strategy: "先完成独立工作，空闲时再等待用户输入和 worker 事件。"
  }
});

长等待使用公开 await 或 events 工具，默认且最长为 55 秒；JavaScript 内的 events.wait 默认且最多等待 1 秒。跨窗口保留 wait_id，处理后分别确认事件和等待结果游标；输入事件只负责唤醒，正文仍通过原输入通道领取。见 订阅、绑定与等待示例。

技术说明 · 扩展

在独立 Git 仓库中维护工具

ssmcp-tools 提供 Code Mode 的官方 JavaScript helper。项目与全局仓库可扩展或覆盖编排函数，并独立提交、测试和管理 Git 历史。

来源位置启用条件
项目当前工作区的 ./.ssmcp/tools/可信 RC 的 tools.projects 精确登记规范化后的工作区绝对路径
全局~/.ssmcp/tools/可信 RC 中 tools.global = true
官方$XDG_DATA_HOME/ssmcp/tools/official，默认 ~/.local/share/ssmcp/tools/official使用所选客户端的官方源码

加载顺序是官方 → RC 中按序列出的 overrides → 已启用全局 → 已登记项目。后加载的同名导出覆盖前者。项目按规范化后的绝对工作区精确匹配，不向父目录查找；创建目录或克隆仓库不会自动启用。

ssmcp tools paths
ssmcp tools init project --git
ssmcp tools init global --git
ssmcp tools status

在要登记的项目目录执行项目命令。paths 只查询位置；init 离线创建工厂、manifest 和 README，再登记来源。--git 创建独立 Git 仓库，不自动提交或添加远端；已有目标保留并返回错误。已有源码用 ssmcp tools enable project 登记，用 ssmcp tools disable project 停用并保留文件；全局来源把 project 换成 global。

可信 RC 位于 $XDG_CONFIG_HOME/ssmcp/ssmcprc.toml，默认是 ~/.config/ssmcp/ssmcprc.toml。修改后，在新的 MCP code_mode 调用参数中明确选择要维护的客户端：

{
  "tool_client_id": "CLIENT_ID_FROM_LIST",
  "code": "return 'sources loaded';"
}

核对外层 structuredContent.tool_sources 中实际加载的来源、路径、SHA-256 和 Git HEAD／dirty 状态。JavaScript 编排可以独立迭代，新调用重新加载所选来源；新增底层原语仍需相应 CLI／中继版本。同名覆盖不改变宿主身份、权限和原生参数校验；选中来源损坏时调用明确失败。

ssmcp tools check 获取官方上游状态；ssmcp tools update 只快进清洁的官方仓库。项目与全局仓库使用各自的 Git 工作流维护。

维护可复用工作流

Dreaming 可使用已有执行、文件和 Git 操作维护这些仓库与工作流。初始化不会启动模型或调度器。完整规则见 工具仓库管理，源码选择见 加载与回执。

Web、原生桌面、Android 与 iOS 的源码入口和验收范围见 客户端概览；HTTP 接入与配对协议见 GUI 网关说明。

文档随服务器构建更新，具体能力以目标客户端返回的工具 schema 为准。安装器获取已经公开的版本，新功能需要相应客户端进程。

技术说明 / 01

先发现接口，再调用工具

list 返回在线客户端。选中一台后，在 code_mode 中查询它当前注册的工具与参数 schema。不同版本或加载状态可能有不同目录，应使用实际返回的接口。

const clientId = "ID_FROM_LIST";
return await tools.search(clientId, {
  name_prefix: "ssmcp.fs.",
  query: "read",
  limit: 5,
  include_schemas: true
});
能力如何工作
命令与文件在客户端工作区执行命令、读取文件。执行结果应包含真实输出与退出状态；一次读取不等于完整作业日志。
异步任务与等待启动任务后按 ID 读取或等待。有界等待超时不表示任务完成；取消观察与取消底层任务是不同操作。
消息与协作使用当前连接中登记的真实成员和消息回执。对方的完成状态不能替代用户对结束请求的批准。
额外 MCP 工具可选 harness 按需显式加载。ssmcp.harnesses.list 查看缓存状态，ssmcp.harnesses.load 加载指定项；原参数和审批规则继续生效。
示例：返回实际图片

每次 code_mode 调用都有独立作用域。客户端 ID 和文件路径必须来自实际选择的工作区。

const clientId = "ID_FROM_LIST";
image(await call(clientId, "ssmcp.fs.read_image", {
  path: "assets/chart.png"
}));

桌面与浏览器：直接使用 Zuse CLI

SSMCP 的 computer 入口只管理独立 Zuse CLI 的版本、下载、安装和卸载。实际桌面或浏览器程序通过通用命令执行；SSMCP 不再内置浏览器控制、私有桌面动作或 Playwright 专用桥。

ssmcp computer version --json

先检查返回的可用状态和路径，再按所选 Zuse 版本的帮助编写程序。受管安装不修改 PATH，也不会接管系统或自行安装的版本。见四项管理命令与 Zuse 使用指南。

技术说明 / 02

清楚理解状态与权限

工具使用本机权限

通用命令以启动客户端的系统权限运行。连接授权控制谁能调用 SSMCP，不会撤销同一系统用户通过其他程序获得的权限。

结束需要真实决定

活动页的“问题待答”表示有可回答的问题，按 Shift+↑ 打开 Questions。它不等于正在阻塞；只有真实 active 的 ui.wait 才显示红色等待倒计时。

发送消息时选择 finish_task: true，或调用 ui.wait 的 intent: "finish"，会复用真实结束问题等待你批准。超时、中断、普通“Yes”消息都不构成批准；未获准的返回结果要求 Agent 继续调用阻塞等待。

订单状态以服务端为准

流量与订单显示当前价格、额度和到期时间。税前金额与含税应付金额按页面及收银台说明核对；返回订单页不等于付款已经入账。

参考

遇到问题，先核对这几项

没有在线客户端

检查本机客户端仍在运行；应用和客户端使用同一中继、同一个获准 GitHub 账户；再刷新 list。被控设备使用允许名单时，还要核对完整服务器用户名。

安装后找不到 ssmcp 命令

重新打开终端，确认安装命令实际成功。使用发行页面核对系统与架构，不要把安装输出中的错误当成成功。

消息已排队，为什么还没有回复

保持 AI 对话工作，让 Agent 有机会进行后续工具调用。检查当前接收者和 /queue；递送回执只说明消息进度，不说明任务完成。

工具目录里没有某项能力

先确认选中的客户端和版本，再查询实时目录。外部 harness 需要显式加载；旧内置浏览器与桌面调用应迁移到独立 Zuse CLI。

已经付款，订单仍在处理中

在订单详情页查看服务端状态。收银台跳回、地址里的查询参数都不能代替付款确认。跨月迟到的付款可能需要管理员核对退款，不能当作已获得本月流量。
