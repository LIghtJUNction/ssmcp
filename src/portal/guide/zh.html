ssmcp使用指南
English简体中文

你的电脑，你的工具。

把 AI 对话，
连接到电脑上的工作。

ssmcp 把电脑连接到支持 MCP 的应用。MCP 是调用工具的协议：应用提出操作，连接的电脑执行命令，结果返回应用并显示在终端里。

开始连接查看使用场景 ↓

二维码只打开公共使用指南，不包含登录码或会话凭据。

01 / 开始

连接电脑，选择工具。

  1. 安装客户端。

    从 GitHub Releases 获取适合系统的客户端。Windows 安装器会为内置浏览器工具准备 Node.js、Playwright 和 Chromium；安装后在需要处理的项目目录里打开终端。

  2. 连接这台电脑。

    在网关账户页面选择账户名，再运行下面的命令。出现授权提示时，按流程使用 GitHub 登录。

    ssmcp yourname@{{gateway_authority}}

    把 yourname 换成你的账户名。之后直接运行 ssmcp，可以复用上次已授权的账户。

  3. 把网关添加到 AI 应用。

    使用下面的 MCP 地址，并授权同一个 GitHub 账户。让应用列出在线客户端，选定要操作的电脑后再调用工具。

    {{gateway_origin}}/mcp

    AI 运行在你的应用或已安装的 harness 中。连接 ssmcp 本身不会启动模型。

02 / 设备与桌面

让另一台设备临时接入。

生成设备邀请。

在已经登录的电脑上运行 ssmcp invite，把生成的完整命令复制到另一台设备。命令从同一网关下载并校验客户端，安装到用户目录后，启动临时连接。

ssmcp invite
ssmcp invite --shell powershell

邀请只能兑换一次，通常在 10 分钟后失效；兑换后的连接最多使用 1 小时，并受原授权剩余期限约束。结束被控设备上的进程即可停止该会话。已安装兼容客户端时，可加上 --no-bootstrap。

从已授权的 MCP 应用发出邀请

让已连接的应用调用公共 invite 工具。它使用应用当前的授权，无需先取得在线客户端 ID。目标是 Windows 时，把 shell 改为 powershell。

{"ttl_secs": 600, "session_ttl_secs": 3600, "shell": "sh"}

在私有桌面里操作应用。

桌面观察和输入默认使用当前连接的私有显示。在 Linux 上，启动已安装的应用时会按需创建这个显示；你正在使用的桌面保留鼠标位置和焦点。

在私有桌面打开编辑器。
检查文档，并截图展示结果。

私有桌面需要 Linux、Xvfb 以及状态工具列出的辅助程序。其他平台会报告缺少的支持；只有调用者明确选择 desktop: "host"，才会操作日常桌面。浏览器页面控制是独立入口。

03 / 日常输入

写下需求，附上上下文。

按 Enter 后，请求进入队列，交给选中的成员或下一次符合条件的 Agent 交互。工作继续执行时，你可以接着写下一条草稿。保持 AI 对话在工作，让 Agent 有机会接收排队的输入。

输入作用
@src/main.rs引用工作区文件。路径有空格时使用 @"文档/使用 说明.md"。
@assets/chart.png引用图片，供 Agent 实际读取。原生读图支持 PNG、JPEG、GIF、WebP，每张图片上限 400 KiB。
$skill-name引用可用的项目或用户技能。输入前缀后用 Tab 或 Enter 接受候选，再按 Enter 发送。
!git status --short在当前工作区运行本地 shell 命令，显示输出和退出状态。
草稿起点按左方向键打开 Agents。上下键选择成员，Enter 或右键确认；Esc 返回并保留草稿。
/queue · /copy查看排队请求，或复制最新一条完整的 Agent 回复。
F1 · F7打开可滚动帮助，或暂停终端鼠标捕获，用终端自己的方式选择文字。

@ 引用使用已授权的工作区。剪贴板内容可通过 /paste 导入，图片可使用 /attach PATH。超过 8 KiB 的粘贴会保存成文件引用，你仍可在后面补充简短需求。

04 / 使用场景

从一个明确的结果开始。

修改项目

提供相关文件和具体目标，让 Agent 检查改动、运行相关验证，并解释结果。

@src/main.rs 修复已报告的错误。
运行相关测试，并展示 diff。

跟进长任务

让 Agent 启动构建、测试或报告任务，再持续查看输出。只要客户端保持连接，托管任务可以在一次 code_mode 调用返回后继续执行。

运行一次测试集。
跟踪任务 ID，最后报告退出码。

检查图片或报告

把图片和要回答的问题一起发出。Agent 通过原生读图工具获得实际图片内容。支持图片的终端显示真实像素，其他终端显示带尺寸的紧凑附件卡片。

@assets/chart.png
解释变化趋势，指出不清楚的标注。

验证浏览器流程

浏览器操作优先使用内置工具。需要特定的已有浏览器会话时，明确选择它的已授权连接；只有该路线需要时，才加载可选的 Playwright harness。

检查已打开的结账页面。
测试表单，并截图展示结果。

协作处理多台设备

ssmcp list 列出已授权的在线设备；终端中的 Agents 面板选择当前连接里的成员。先确认电脑，再选择本条请求的接收者。

在已选中的构建机上，
检查最近一次构建结果。

带着上下文继续工作

/resume 打开已保存的对话；/context 和 /memory 查看本地分支记忆；/handoff 生成上下文文件草稿，再由你选择接收者。

/handoff 继续排查失败的测试。

恢复对话不会重新执行工具，也不会重发旧请求。

05 / 工具调用

以当前客户端的接口为准。

先用 list 获取选中客户端的 ID。在 code_mode 中查询它实际注册的工具，读取返回的 schema，再发起调用。内置工具不依赖其他 harness。可选 harness 默认不加载：ssmcp.harnesses.list 读取缓存状态，ssmcp.harnesses.load 明确加载一项；加载后的原始参数与审批规则保持有效。

const clientId = "ID_FROM_LIST";
return await tools.search(clientId, {
  name_prefix: "ssmcp.fs.",
  query: "read",
  limit: 5,
  include_schemas: true
});
示例：向应用返回实际图片

每次 code_mode 调用都有独立作用域。请在调用里写明选中的客户端 ID，并使用该客户端工作区中的路径。

const clientId = "ID_FROM_LIST";
image(await call(clientId, "ssmcp.fs.read_image", {
  path: "assets/chart.png"
}));

遇到问题，先检查这几项。

没有在线客户端？
保持本机客户端运行，确认应用和客户端使用同一个已授权账户与网关。
找不到某个工具？
刷新客户端列表，再查询选中客户端的实时工具。内置工具默认可用；需要外部 harness 的能力时，先显式加载该项，再查询更新后的工具目录。
二维码放不下？
侧栏会改为显示可读链接。终端较小时，F1 帮助仍保留完整的指南地址。
