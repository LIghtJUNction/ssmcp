YOUR COMPUTER. YOUR TOOLS.

A bridge from your AI app
to the work on your computer.

ssmcp connects a computer to an app that supports MCP, the protocol for calling tools. Commands run on the connected computer. Their results return to your app and appear in the terminal.

This QR code opens public documentation. It contains no login code or session credential.

01 / START

Connect once, then choose your tools.

  1. Install the client.

    Get the client for your system from GitHub releases. Open a terminal in the project folder you want to work with.

  2. Connect this computer.

    Choose your account name on the gateway account page, then run the command below. Follow GitHub authorization when prompted.

    ssmcp yourname@{{gateway_authority}}

    Replace yourname with your account name. On later visits, ssmcp can reuse your last authorized account.

  3. Add the gateway to your AI app.

    Use this MCP address and authorize the same GitHub account. Ask the app to list online clients, then select the intended computer before calling a tool.

    {{gateway_origin}}/mcp

    The AI runs in your app or an installed harness. Connecting ssmcp does not start a model.

02 / DEVICES & DESKTOPS

Give another device temporary access.

Create a device invitation.

On a computer where you have already logged in, run ssmcp invite. Copy its generated command to the other device. The command installs the client from the same gateway into the user's directory, checks the download, then starts a temporary connection.

ssmcp invite
ssmcp invite --shell powershell

The invitation is single-use and normally expires in 10 minutes. The resulting connection lasts up to one hour, within the original authorization's lifetime. Stop the connected process to end that device's session. Use --no-bootstrap when a compatible client is already installed.

Invite from an authorized MCP app

Ask your connected app to call the public invite tool. It uses the app's current authorization and needs no online client ID. Choose powershell for a Windows device.

{"ttl_secs": 600, "session_ttl_secs": 3600, "shell": "sh"}

Use a private desktop for app work.

Desktop observation and input default to the connection's private display. On Linux, launching an installed app starts that display when needed. Your usual desktop keeps its mouse position and focus.

Open the editor in a private desktop.
Inspect the document and capture the result.

Private desktops require Linux, Xvfb and the helpers listed by the status tool. Other platforms report the missing support. A caller must explicitly select desktop: "host" to operate the usual desktop. Browser page controls remain a separate option.

05 / FOR TOOL CALLERS

Discover the live contract.

Use list to get the selected client's ID. Inside code_mode, search its registered tools and read the returned schemas before calling them. Installed harnesses keep their native arguments and approval rules.

const clientId = "ID_FROM_LIST";
return await tools.search(clientId, {
  name_prefix: "ssmcp.fs.",
  query: "read",
  limit: 5,
  include_schemas: true
});
Example: return a real image to the app

Each code_mode call has its own scope. Include the selected ID in the call, and use a path from that client's workspace.

const clientId = "ID_FROM_LIST";
image(await call(clientId, "ssmcp.fs.read_image", {
  path: "assets/chart.png"
}));

Need a quick check?

No online client?
Keep the local client running and check that your app and client use the same authorized account and gateway.
A tool is missing?
Refresh the client list and search the selected client's live tools. Available capabilities depend on the tools and harnesses installed on that computer.
The QR does not fit?
The sidebar shows a readable link instead. F1 retains the full guide address on smaller terminals.
