User guide · ssmcp {{version}}

Connect once.
Work in your own environment.

ssmcp connects an MCP-compatible AI application to your computer. MCP is a protocol for calling tools: the application sends a request, your computer runs a command or handles a file, and the result returns over the connection.

Connecting does not start a model. The terminal's guide QR code contains a public URL, not login credentials.

Get started / 01

Your first connection in three steps

  1. Install the client

    Choose the command for the computer you want to connect. You can also download a release manually from GitHub Releases.

    Linux / macOS
    curl -fsSL https://github.com/LIghtJUNction/ssmcp/releases/latest/download/install.sh | sh
    Windows PowerShell
    irm https://github.com/LIghtJUNction/ssmcp/releases/latest/download/install.ps1 | iex

    Run ssmcp --version after installation. When it prints the client version, continue to the next step.

  2. Connect from your project directory

    Open a terminal in the folder you want to work on. Replace yourname with your server username and run:

    ssmcp yourname@{{gateway_authority}}

    The first connection guides you through GitHub sign-in. Check the username and device before allowing access. An existing username can only be used by its linked account.

    Keep this terminal running. On later visits, ssmcp can reuse the saved connection configuration. Open the account portal to check your account.

  3. Add the relay to your AI application

    Enter this address in the application's MCP connection settings and authorize the same GitHub account.

    {{gateway_origin}}/mcp

    For example, open ChatGPT Plugins, select Add, fill in Name and Connection, then follow the prompts to Create and authorize the connection.

    Return to the conversation and ask the AI to list online clients. Confirm the computer and working directory before starting a task. If the list is empty, see troubleshooting.

Get started / 02

Connect another device

The person using the device runs the client from the project directory they choose to share. Replace yourname with the controller’s registered username on the same relay. The device needs neither a signed-in account nor a server invitation code. The controller still signs in to their relay account, and MCP apps complete the relay’s OAuth authorization.

ssmcp --server {{gateway_origin}} --allow yourname@{{gateway_authority}}

Repeat --allow or separate entries with commas to allow up to 32 accounts. An explicit list grants access only to those accounts. With an existing valid login, omitting the list allows only yourself. Ending the client process closes the device connection.

How do accounts, devices, and collaboration members differ?

A server account determines who may connect to a device. A client represents a connected computer. A collaboration member registered with collab.join participates in messages and tasks within a session; membership does not replace device authorization.

In the main window, /invite generates instructions for collaborating in a session. Device access remains subject to the connection’s allow list and existing permission checks. Allow lists reject bare usernames, @github, and accounts on another server. Traffic is charged to the actual controller account. Changes to one controller's quota or access do not disconnect other authorized controllers.

Everyday use / 01

Write a request with useful context

Pressing Enter sends ordinary input through the selected message route. You can write another draft while work continues. The AI must keep making tool calls to have an opportunity to receive queued input.

InputWhat it does
@src/main.rsReference a workspace file. Quote paths with spaces, such as @"docs/usage notes.md". A missing file produces a warning; the literal message can still be sent.
@assets/chart.pngLet the agent read an actual image. Native image reading supports PNG, JPEG, GIF, and WebP, up to 400 KiB per image.
$skill-nameReference a project or user skill with its source, metadata and reading information. Read the full skill before applying it; referencing it does not execute it. Use Tab or Enter to accept a completion, then Enter again to send.
!git status --shortRun a local shell command in the workspace and show its output and exit status.
/sessions · /messageChoose a recipient and confirm. Escape returns without discarding the draft.
/queue · /copyInspect queued requests or copy the latest complete agent reply.
F1 · F7Open help, or pause mouse capture so you can select text with your terminal.

The / commands above belong in the SSMCP chat composer, not the system shell. /paste imports the clipboard and /attach PATH attaches an image. Pastes over 8 KiB are saved as file references; you can still add a short request after them.

When does a message include local files?

Ordinary local requests and /send to a local listener prepare @ / $ references. A /send addressed to a native member or group sends literal text, disables reference completion, and does not implicitly attach local files or skills.

queued, included, and acknowledged describe message delivery. They do not prove that someone has read the message or completed the task. Check the actual reply and task result.

Technical reference · Workers

Workers: a bounded local execution pool

Worker mode prepares independent execution slots. Its monitor shows idle, working, offline, total and queued counts, with no chat composer. Select an installed and configured local executor explicitly:

ssmcp yourname@{{gateway_authority}} --worker 10 --agent codex

Execution currently requires Linux, cgroup v2 with CPU and memory controllers, and a usable user systemd manager. Supported executors are codex, claude, opencode and exec. The default next-caller does not launch a model. Missing executors or unavailable hard limits leave slots offline with a reason.

Queue, results and cancellation

A genuinely bound caller submits through ssmcp.worker.submit. Idle slots claim tasks in FIFO order. status inspects the pool, result reads the caller's task, and cancel requests cancellation. A running slot stays busy until owned processes and scopes are confirmed clean. An unknown outcome must not be replayed blindly.

How resource shares work

Per-slot CPU and RAM ceilings use “effective system capacity ÷ registered slots for this OS user × k.” The --worker-k default is 1. These are ceilings, not reserved resources. Other OS users and independently launched commands are outside that count.

Slots keep SSMCP context, not a promised persistent model-native thread, and tasks cannot rely on slot affinity. See the worker technical guide for limits and cleanup behavior.

Technical reference · Extensions

Editable tool helpers

ssmcp-tools contains the JavaScript helpers for code_mode. New clients read registered local sources and return provenance with actual paths, Git state and content digests. Helpers compose calls; those calls still pass through the original authorization checks.

ssmcp tools status
ssmcp tools check
ssmcp tools update

The client RC is $XDG_CONFIG_HOME/ssmcp/ssmcprc.toml, or ~/.config/ssmcp/ssmcprc.toml by default. Git must be available. Updates fast-forward a clean worktree without overwriting local edits. Editing a helper cannot forge server identity, authorization or finish approval.

This guide follows the server build. The selected client's actual tool schema defines its capabilities. Installers fetch published releases; new features need a corresponding client process.

Technical reference / 01

Discover the interface before calling it

list returns online clients. Select one, then use code_mode to inspect its currently registered tools and parameter schemas. Versions and loading state may differ, so use the interface actually returned by that client.

const clientId = "ID_FROM_LIST";
return await tools.search(clientId, {
  name_prefix: "ssmcp.fs.",
  query: "read",
  limit: 5,
  include_schemas: true
});
CapabilityHow it works
Commands and filesRun commands and read files in the client's workspace. Results should include actual output and exit status. One read does not represent the entire job log.
Asynchronous tasks and waitsAfter starting a task, read or wait by ID. A bounded wait timing out does not mean the task completed. Cancelling an observation is different from cancelling the underlying task.
Messages and collaborationUse real members registered in the current connection and their delivery receipts. Another agent finishing cannot substitute for the user's approval of a finish request.
Additional MCP toolsOptional harnesses load explicitly on demand. ssmcp.harnesses.list shows cached state; ssmcp.harnesses.load loads a chosen harness. Its original parameters and approval rules still apply.
Example: return an actual image

Each code_mode call has its own scope. Use the selected client's real ID and a path in that workspace.

const clientId = "ID_FROM_LIST";
image(await call(clientId, "ssmcp.fs.read_image", {
  path: "assets/chart.png"
}));

Desktop and browser tasks: use Zuse CLI directly

SSMCP's computer interface only manages the independent Zuse CLI: version, download, install, and uninstall. Desktop and browser programs run through general command execution. SSMCP no longer embeds browser control, private-desktop actions, or a dedicated Playwright bridge.

ssmcp computer version --json

Check the returned availability and path, then follow the selected Zuse version's help when writing a program. Managed installation does not modify PATH or take ownership of a system or separately installed version. See the four management commands and the Zuse guide.

Technical reference / 02

Understand state and permissions

Tools use local permissions

General commands run with the operating-system permissions of the client process. Connection authorization controls access through SSMCP; it does not revoke the same user's permissions through other programs.

Finishing needs a real decision

The activity page's pending-question badge means there is a question you can answer. Press Shift+↑ to open Questions. It is not proof of a blocking wait: only a real active ui.wait shows the red countdown.

Send a message with finish_task: true, or call ui.wait with intent: "finish", to wait on the real finish question. Timeout, interruption and a plain “Yes” message are not approval. Without approval, the result instructs the agent to call the blocking wait again.

Order state comes from the server

Traffic and orders shows the current price, allowance, and expiry. Check the page and checkout for the pre-tax amount and final amount including tax. Returning to the order page does not mean payment has been credited.

Reference

Check these first

No online clients

Keep the local client running. Confirm that the application and client use the same relay and an authorized GitHub account, then refresh list. For a device allow list, also check the complete server username.

The ssmcp command is missing after installation

Open a new terminal and check that installation actually succeeded. Use the release page to confirm your operating system and architecture. An error in installation output is not a successful install.

A message is queued but there is no reply

Keep the AI conversation working so the agent can make subsequent tool calls. Check the recipient and /queue. A delivery receipt describes message progress, not task completion.

A tool is missing from the catalog

Confirm the selected client and version, then query its live catalog. External harnesses require explicit loading. Migrate old embedded browser and desktop calls to the independent Zuse CLI.

I paid but the order is still processing

Read the server state on the order detail page. A return from checkout or a URL parameter cannot replace payment confirmation. Payment arriving after the month ends may need an administrator's refund review; it does not grant current-month traffic.
