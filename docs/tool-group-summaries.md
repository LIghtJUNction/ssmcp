# 工具组总结

工具组总结给连续工具调用补上一句用途说明。Agent 通过原生工具更新这句话；终端在折叠和展开的工具组标题中显示它，并保留调用次数、运行中、成功和失败状态。

例如，用户可以看到“核对安装包版本”，再展开同一组查看实际调用、命令和输出。总结是 Agent 提供的说明，调用状态仍由真实执行事件决定。

## 原生工具

先发现当前客户端实际注册的 `ssmcp.ui.tool_summary`。它提供两个操作：

| 操作 | 参数 | 结果 |
| --- | --- | --- |
| `list` | `action: "list"` | 列出当前授权范围内最近最多 32 个可更新的工具组，包含稳定的 `group_id`、当前总结与 revision。 |
| `set` | `action: "set"`、`group_id`、`summary`，可选 `expected_revision` | 更新指定组的总结并返回新 revision。 |

`summary` 是非空单行纯文本，最多 120 个 Unicode 字符、512 个 UTF-8 字节。空白、控制字符和越界内容会被拒绝；显示内容使用现有脱敏路径。总结不支持 Markdown，也不会加入普通聊天正文。

通过 code mode 调用：

```javascript
// clientId 来自本轮 list；先读取该客户端的真实工具 schema。
const groups = await call(clientId, "ssmcp.ui.tool_summary", {
  action: "list"
});
return groups;
```

从返回结果选择要说明的准确 `group_id`，然后提交：

```javascript
return await call(clientId, "ssmcp.ui.tool_summary", {
  action: "set",
  group_id: groupId,
  expected_revision: revision,
  summary: "核对安装包版本，并检查下载失败原因"
});
```

列表的 has_more／truncated 表示还有更早的组。

同一组可以更新多次。带上 `expected_revision` 后，旧版本更新会失败，调用方应先重新读取该组。更新只修改组说明，保留展开状态、滚动位置、选中项、草稿和光标。

## 自动提醒

连续工具调用超过 10 次时，系统提示 Agent 调用总结工具；第 10 次不触发，第 11 次触发。提醒带有准确的组标识，不能用当前屏幕行号代替。

成功更新总结后，以当前调用数量作为新的计数起点。再新增 11 次调用时，系统提醒更新说明。相同组、相同总结 revision 的提醒会去重，避免后续每次返回都重复提示。

计数针对真实逻辑工具调用。开始、完成、stdout 等同一次调用的生命周期更新不会重复累计。总结工具和系统内部观察请求不增加工作调用计数，也不会把同一组拆开。

提醒通过真实原生工具响应进入 relay，再由 relay 加到外层响应。它是现有工作的说明提醒，不是新用户需求；JavaScript 返回值中自造的提醒字段不能触发这条链路。

## 会话与调用者范围

工具组使用稳定标识，当前页面的位置和显示名称不作为写入依据。更新同时核对原始会话、连接和真实账号。已绑定 Agent 的调用还需匹配准确线程；未绑定的调用只操作同一授权范围内的未绑定组。

用户切换会话后，迟到的总结仍属于原来的组。其他调用者、旧连接或越权请求不能通过猜测组标识修改它。刷新后的列表反映当前可更新范围。

终端重载会保留有界的总结显示，但恢复内容只读，不恢复旧连接的写入权限。新的工具调用创建新的活动组。旧快照没有总结字段时仍可读取。

## 验证

运行针对性的 Rust 测试以及 `scripts/e2e_tool_summaries.py`，覆盖 10／11 次边界、更新后的计数、revision 冲突、调用者隔离、真实外层提醒与终端标题。真实终端验收同时保留 120 列和 48 列截图。

源码测试、原生端到端验收和实际运行版本分别记录。新的原生工具由客户端提供；外层自动提醒需要 relay 同时支持该响应处理。
