# SSMCP 0.10.15

本候选把 Project Z 依赖更新、交互协议和 v0.10.14 发布检查发现的修复组合到同一应用版本。当前仍在统一构建与验收；本文件的功能说明对应候选源码，不表示版本已经正式发布或部署。

## 结束请求有明确的授权过程

代理提交结束请求时必须说明原因。终端默认选择“否”，评论是独立输入；在评论中写“yes”不会成为批准。结束请求有有界等待和可继续查询的请求标识，等待超时不代表获准结束。

用户可以在终端决定，另一个经过验证、具备相应权限的代理也可以参与决定。发起者不能自行批准自己的结束请求。批准只允许匹配的请求作用域提交一次最终回答；连接或相关状态变化会使旧批准失效。

该约束作用于经过 SSMCP 的明确最终回答与完成操作。外部聊天应用的结束按钮或最终回复不在 SSMCP 能拦截的范围内。

## 异步问题保持原始接收对象

普通问题提交后立即返回，不占住工具执行槽等待用户输入。终端可通过 Shift+Up 打开待答问题；回答保留为独立的结构化结果，在原提问线程下一次合适的工具响应中送达。

身份来自已经验证的账号、连接和线程。控制器显示名称不会决定回答归属，也不会把回答交给下一个任意调用者。显式查询问题不会悄悄消费回答；没有绑定线程的调用保留明确的手工读取路径。

## 原生消息使用明确的收件人和回执

原生消息独立于用户需求队列。收件人选择器展示可用目标，消息携带来源与目标信息，并区分排队、加入响应、确认和过期等状态。

账号权限、连接和成员有效性会在相关操作时重新检查。断开连接、退出协作或权限改变会使不再有效的待投递消息过期。消息正文按文字处理，包含 @路径 或看似命令的内容不会触发文件读取或命令执行。

当前消息状态保存在活跃服务实例内，不承诺服务器重启后的持久投递。协作消息也不会被升级为用户的新指令。

## 长粘贴保留可恢复的原文

超过 4 KiB 或达到 8 行的粘贴文本可保存为工作区内的私有输入文件，短文本继续在输入框中编辑。文件创建失败时保留原始文本并提供恢复路径；失败不会让用户丢失刚粘贴的内容。

## Project Z 与桌面输入

候选使用 zuse-computer 0.2.1、zharness 0.5.1、zplugin 0.3.1 和 ztuio 0.1.0 的固定来源。依赖版本、精确提交和传播要求见 [依赖说明](dependencies.md)。

X11 文本输入将整段文字交给底层库处理，保留整段输入前置检查与可访问性后端选择。已经发出输入后才观察到的取消会明确提示可能已有变化，避免无条件重试造成重复输入。

本轮同时包含尚未正式发布的 v0.10.14 应用修复：只接受经过验证的旧客户端自身账号兼容映射；私有 Xvfb 使用明确的高位显示编号和资源归属检查；OpenCode 订阅关闭不再等待同步归档锁释放后才关闭连接。

## 验收和发布方式

本地验收包含完整 workspace 测试、真实 WebSocket、旧客户端兼容、私有桌面和实际终端交互。新交互脚本已接入正式发布检查，记录固定源码与二进制摘要，并保存实际终端帧。

正式发布前还需完成六个平台的检查和产物验证。发布产物与生产服务切换可以分开执行；本次生产切换仍等待其他项目活动任务的安全交接。v0.10.14 的失败标签保持不变，其构建产物没有被作为正式 Release 发布。

具体通过结果、失败记录与部署状态以 [迭代验收报告](reports/history-resume-20261120/README.md) 和对应正式工作流回执为准。
