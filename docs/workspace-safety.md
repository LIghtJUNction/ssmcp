# 原生文件安全预检

安全预检覆盖 `ssmcp.fs.write`、`ssmcp.fs.write_text`、
`ssmcp.fs.edit_text` 和 `ssmcp.fs.mkdir`。请求先经过路径与规则裁决，
允许的请求继续交给现有原生文件执行器。实际工作区范围、符号链接处理、
写入锁、内容哈希前提和原子替换仍由文件执行器检查。

## 默认行为与显式配置

未启用用户策略时，普通工作区相对路径可以继续使用，包括
`.ssmcp/safety` 和大小写不同的同名目录。绝对路径和父目录遍历被预检拒绝。
尚未成功启用策略的工作区，在本次检查没有发现用户基线候选时，使用内置路径
预检。这包括缺少 HOME、路径不存在，以及 HOME 或配置目录含符号链接、无法
访问或不是目录而不能发现基线的情况。加载器不会为了选择配置而跟随符号
链接。仅有项目规则文件不会启用策略；没有基线候选时，HOME 的组写权限也
不会自行启用一条拒绝规则。非 UTF-8 的 OS 路径分量可以正常发现和加载基线。

Linux 可从 `~/.ssmcp/safety/baseline.toml` 加载用户基线。基线决定是否读取
工作区的 `.ssmcp/safety/rules.toml`。下面的配置拒绝文本写入，并选择加载
项目规则：

```toml
project_rules = true

[operations]
"ssmcp.fs.write_text" = "deny"
```

项目文件只接受同样的 `[operations]` 表。它可以增加限制，无法放宽用户
基线的裁决。可配置的操作就是上述四个原生工具；未知字段、未知操作和无效
值会使所选择的策略不可用。未选择项目规则时，不读取项目文件。

规则值为 `allow`、`require_approval` 和 `deny`，由 zguard 按限制更强的
结果合并。当前版本没有与原请求绑定的审批完成入口，因此显式配置
`require_approval` 会阻止相关操作。默认路径规则不额外要求审批。

## 重载与恢复

每个工作区运行时在原生变更请求到来时检查配置，最多每秒一次。规则和加载
状态一起发布为内存快照；相关状态或有效规则变化时，规则版本随之递增。

| 当前情况 | 发布的状态 | 受控变更 |
| --- | --- | --- |
| 尚未成功启用策略，本次未发现基线候选 | `builtin` | 使用内置路径预检 |
| 用户基线及已选择的项目规则均有效 | `active` | 使用合并后的规则 |
| 首次发现基线候选，但无法完成可信加载 | `configured_unavailable` | 拒绝 |
| 曾成功启用策略，此后无法发现基线、基线无效或失去信任，或所选项目规则无法加载 | `active_unavailable` | 拒绝 |

首次加载失败不会记录为成功启用；后续检查未发现基线候选时，工作区会回到
`builtin`。同一次检查已经发现候选后，即使它在打开前消失，也按加载失败处理。
曾成功启用策略后，删除文件或让路径无法发现不会自动撤销此前的保护。要明确
恢复普通行为，可以提供一份有效的空基线文件；其默认值不选择项目规则，也
不增加操作限制。

项目加载失败时，新近有效的用户基线仍可保留在故障快照中，但所有受控变更
都会拒绝。此前允许操作的旧快照不能在故障期间继续授权。修复配置后，下一次
到期检查可发布有效策略。快照不跨进程保存。

## 文件读取与信任范围

加载器通过不跟随符号链接的目录描述符逐级查找基线叶节点。发现叶节点就
选中了本次检查的候选；叶节点自身是符号链接、断链、不可读文件或非普通文件，
都不能再视为未配置。随后检查 HOME、配置目录和文件的信任条件。读取前再次
确认原路径仍指向已发现候选，再通过保留的描述符打开这个固定文件，并核对读
描述符的身份和版本。HOME 与配置目录、规则文件必须由
当前 OS 用户拥有，且不允许组或其他用户写入；HOME 的上级目录允许可信的 root
所有目录，以及 root 所有的粘滞临时目录。

每份规则必须是普通、单硬链接文件，最多 16 KiB，正文必须是有效 UTF-8 TOML。
读取前后检查同一文件描述符的身份、权限、所有者、链接数、长度及修改时间、
状态变更时间；两层解析结束后再次检查保留的描述符及目录信任条件。读取期间
可观察到的内容或权限变化
会使该次加载失败。写入配置时，可先在同目录写好临时文件，再进行原子替换；
正在读取的旧描述符保持指向原文件，若复查发现链接数或版本变化则稍后重试。

这些检查提供一次有界读取的快照，不锁住同一 OS 用户的所有文件操作。有效
快照可能使用至下一次检查；外部进程、传输、删除和密钥外发不属于此预检范围。
实际原生文件访问仍受原有工作区检查约束。

实现见[加载器](../src/workspace/safety/linux.rs)和
[快照状态](../src/workspace/safety/rules.rs)；相关边界用例见
[回归测试](../src/workspace/safety/rule_tests.rs)。

## 读取裁决记录

`ssmcp safety` 或 `ssmcp safety status` 显示本地版本的覆盖范围。
拥有相应会话访问权的调用方可以通过 `ssmcp.fs.events` 的
`stream: "safety"` 读取有界内存裁决流。默认的文件审计流保持独立游标和
原有事件内容；安全裁决只记录工具、策略、规则版本、加载状态、裁决与结果，
省略路径、内容、参数和加载错误细节。

对于正在运行的本地已保存会话，`ssmcp safety --local NAME` 使用只读 attach
租约，展示最近 128 条裁决中的阻止和执行失败。`ssmcp safety inspect EVENT_ID --local NAME`
读取其中一条事件。事件 ID 绑定会话运行代与后端代，过期或被淘汰的记录无法
读取；它只标识证据，不授予审批或重放权限。读取结果也不依赖远程模型在线。
