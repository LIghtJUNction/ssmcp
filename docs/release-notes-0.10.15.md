# SSMCP 0.10.15

## 已登录客户端连接旧 relay

直接运行 `ssmcp`，或指定自己的已登录账号时，旧 relay 可能拒绝新版名单格式。客户端现在仅在注册完成之前收到这一精确拒绝时，重新验证当前账号，再以同一账号的自身权限重试一次。验证检查同一服务器的现有凭据、稳定账号 ID、保存的登录身份和服务器真实注册用户名。账号所有权和额度保持一致，终端会显示兼容提示。[连接实现](../src/client.rs) · [身份检查](../src/client/account.rs)

旧格式拒绝现在属于永久错误；不能安全兼容时会停止，不再每五秒无限重试。

## 显式认证兼容模式

旧 relay 尚不支持匿名名单，但本机已有该 relay 的有效登录时，可明确使用：

~~~sh
ssmcp --account-compat --allow alice@ssmcp.lmm.best
~~~

只允许名单恰好为当前已验证账号。此连接由该账号拥有，沿用账号额度和管理、审计权限；它不会提供登录码或委派能力。缺少有效凭据、账号绑定不一致、多账号或跨服务器时直接失败，不会发起 OAuth 或注册用户名。

普通 `--allow` 继续采用匿名注册，不会自动携带本机登录凭据。新 relay 的多账号名单行为保持原样。[账号使用说明](client-accounts.md)

## 发布与服务器升级

本版本继续使用六个平台的正式构建、制品校验、包发布及发布门禁。**0.10.15 强制禁止 Release 工作流自动部署服务器**，包括显式传入 `deploy_server=true` 的重试。服务器切换需要单独验证不会打断现有连接。

新增 `scripts/inspect_server_upgrade.py` 只读取升级现场并给出预检结果；它不会授予重启许可，也不会复制运行状态。[发布流程](releases.md) · [修复验收](reports/account-compat-20261120/README.md)

[0.10.15 候选版说明](release-notes-0.10.15-candidate.md)保留了当时的功能和验收计划。
