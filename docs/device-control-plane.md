# 多设备控制平面与恢复

状态：P0 实现与验收进行中；P1、P2 是后续阶段。源码提交、实际测试结果和运行中的服务版本分别记录。本文不表示线上服务已经更新。

## 产品入口与目标

CLI 面向专业开发者，提供脚本、精确寻址、批量操作和诊断能力。Windows 的常规使用优先推荐桌面版；桌面端围绕同一个 CLI 核心管理连接与工作，不另建一套权限或执行系统。

同一个 `name@server` 是服务器上的账号入口，可以同时拥有多台设备和多个会话。一个 MCP 端点列出当前调用者有权访问的连接，每次操作明确指定一个当前连接。对 N 个目标的操作由调用者显式列出 N 个 ID，并分别记录结果；不会因为选中了账号、设备组或相同名称就自动广播。

## 三层身份

| 字段 | 表示什么 | 何时变化 |
| --- | --- | --- |
| 账号 subject | 经服务器验证的账号归属 | 更换账号时变化；显示用户名变化不转移归属 |
| `device_id` | 同一服务器、同一账号下持有安装签名密钥的设备身份 | 删除或替换设备密钥、切换账号或服务器时变化 |
| `session_id` | 设备下的一个保存会话定义或本次前台进程 | 保存定义重启时保持；删除重建或重新打开前台进程时变化 |
| `client_id` / `routing.connection_id` | 当前这一次网络连接 | 每次重新连接都变化；旧 ID 不能调用替代连接 |
| `routing.alias` | `work@laptop.local` 形式的显示标签 | 名称或主机名变化时更新；同名可以重复 |

设备 ID 由服务器使用已经验证的账号、服务器 origin 和经过签名验证的公钥派生。客户端不能提交另一个设备 ID 来覆盖已有连接。登录 token 的更新不改变设备签名密钥，因此正常重新授权后的设备 ID 保持一致。设备身份代表密钥持有者，不是物理硬件证明；复制整个私有密钥目录会复制该身份。

保存会话在自己的私有目录中保存随机 `definition_id`。它参与稳定会话 ID 的派生，并供 007 核对恢复目标。前台进程只在本进程内保留随机会话键，因此网络重连仍是同一会话，进程退出后不会冒充已经消失的作业集合。

`.local` 在这里仅是标签格式，`alias_kind` 明确为 `display_only`。产品不会注册 mDNS、修改 DNS 或承诺该标签能够解析。RFC 6762 为真正的 `.local` 名称规定了链路本地 mDNS 语义；公网 FQDN 应由独立、明确配置的 DNS 记录提供。[1] 重名时使用完整设备、会话与连接 ID 消歧，不能取搜索结果的第一项。

## P0：注册、发现与精确路由

客户端复用现有 HTTPS/WSS、服务器信任配置和账号认证。身份注册增加一个有界步骤：

1. 使用当前账号凭据请求 30 秒有效的随机挑战。服务器把挑战绑定到已验证账号及该凭据。
2. 本机为这个服务器保存 Ed25519 安装密钥。客户端签名 origin、凭据摘要、公开会话键和挑战，随 WebSocket 握手提交证明。
3. 服务器验证签名并在同一临界区消耗挑战。已使用、过期、跨账号、跨凭据、跨 origin 的证明均不能再次使用。
4. 服务端分配新的 `client_id`。同一个稳定会话仍在线时，第二条连接被拒绝；不会抢占、静默覆盖或重定向已有连接。
5. `list` 返回当前可调用的 `clients`，以及账号所有者可见的 `device_sessions` 最近状态。离线记录最多保留到本次 broker 生命周期结束或断线后 24 小时；达到容量时可淘汰最旧离线记录。它不是可执行权限或完整历史数据库。

签名使用项目现有的 ring 实现，私钥保存为带一致性检查的 PKCS#8 v2 文件；不自定义签名算法。[2] 私有账号目录和文件沿用当前用户权限校验及串行写入锁。损坏的密钥文件报错，不自动覆盖。

```javascript
// list 支持按完整稳定地址重新发现当前连接。
// 下面是 MCP list 的参数，不是把显示别名当 DNS 地址。
{ device_id: "dev_<64 个小写十六进制字符>",
  session_id: "ses_<64 个小写十六进制字符>" }

// 发现后仍对每个明确选择的当前 client ID 获取 schema 并调用。
const results = await Promise.allSettled(selectedClientIds.map(async (id) => {
  await tools.search(id, { query: "status", include_schemas: true });
  return call(id, exactDiscoveredToolName, argumentsForThisTarget[id]);
}));
```

地址过滤只影响发现，不执行工具。每次调用继续经过现有账号、资源范围、会话 ACL、绑定和队列派发时的权限检查。共享给其他账号的在线会话仍遵循明确 ACL；以前的受邀者不能通过离线所有者目录继续观察已经撤销的访问。旧客户端没有证明时保留原连接语义，不伪造稳定地址。新客户端只对明确不支持挑战端点的旧服务器降级为旧连接；认证失败、无效证明或服务故障不降级为匿名连接。

现有限制为每个用户 128 个在线连接、每个连接 16 个在途调用。注册挑战最多全局 4096 个、每账号 128 个未使用挑战和每分钟 256 次签发。最近会话目录最多 8192 项。服务器与客户端采用 75 秒无入站消息超时，服务器每 25 秒发送心跳；这些限制避免断开的连接无限占用在线身份。流量计费、审计及现有账号限流继续在原边界执行。

## 断线恢复和结果状态

恢复首先保留原任务 ID、worker claim、提交 ID、原连接、设备/会话身份、输出游标和未完成步骤。重连成功只证明控制通道恢复，不证明之前的命令完成，也不恢复已经结束进程的内存作业。

| 观察结果 | 动作 |
| --- | --- |
| 暂时断线或超时 | 在有界退避窗口内重试原连接和只读发现；核对稳定地址和实际新连接 |
| 007 在线且保存定义身份匹配 | 先串行读取 status/list；仅恢复匹配、未明确停止且仍有授权的原定义 |
| 已明确停止、退休或撤权 | 停止自动恢复；不能通过 007、重新登录或替代名字绕过 |
| 007 不可用、机器离线或目标身份不明 | 保留可恢复检查点并报告阻塞；不能报告任务完成 |
| 请求可能执行但回执丢失 | 保持 `unknown`；查询原回执、文件、提交或外部状态，不自动重放 |

007 的进程 `active` 与正式会话 `connected` 是不同观察。007 每次最多执行一个管理请求，调用必须串行；管理调用超时后先检查原定义和管理器状态，不能自动再次 wake。手动终端若没有对应的 007 保存定义，不能仅凭相同工作目录或名称推断可恢复对象。

## P1：安全直连与中继回退设计

P1 尚未计入 P0 的完成范围。服务器继续负责账号、设备身份、权限、协商和审计，数据通道优先尝试经过相互认证的直连。ICE 候选检查可以帮助选择可达路径，但不保证存在公网直连路径。[3] STUN 用于发现映射，必要时使用 TURN 或现有中继；UDP 不可达时需要明确的 TCP/TLS 路径，不能把开放公网端口当作无条件可达证明。

会话授权票据应绑定双方设备 ID、稳定会话 ID、当前连接代次、候选集合摘要、短有效期和一次性 nonce。数据通道使用成熟的 DTLS/QUIC/TLS 实现；不复用 bearer token 作为数据加密密钥。重放窗口、连接迁移、NAT 映射变化、心跳超时、流控和路径切换都必须在通道状态机中显式处理。回退只重建承载路径；已经派发且结果未知的应用操作保持原 ID，不能因换路再次执行。

签名密钥轮换需要旧密钥和新密钥的双向证明、服务器原子映射更新、短重叠期与撤销记录；账号 token 续期和设备签名密钥轮换不是同一操作。P0 支持前者，后者在实现前不能宣称设备 ID 不变。

验收需要抓包证明成功直连时业务数据没有经过中继；不可达候选应在有界时间内回退，分别记录恢复耗时、丢失与未知操作。只有控制面日志中的“直连成功”不足以证明数据路径。

## P2：发现、体验与规模

P2 再扩展设备组、搜索、离线告警、持久目录、可选真实 mDNS/FQDN 集成和更大规模的路由分区。可以借鉴 Kubernetes 把控制面、节点注册与心跳租约分离的结构，但不会引入 Docker/Kubernetes 运行依赖。[4] Windows 桌面版优先展示设备、会话、任务进度与异常，详细协议和命令日志按需展开。

## 验收记录要求

P0 验收应覆盖至少 10 个同账号设备的并发连接和逐目标调用，跨账号拒绝、同名冲突、主机改名、重连后的新连接 ID、旧 ID 失败、并发证明重放、离线恢复及明确停止。100 个模拟设备的长测必须真实持续 1 小时，分别记录实际时长、成功与失败次数、延迟分位、应用吞吐、服务器数据量和 CPU；短测不能改名为长测，模拟设备也不能写成 100 台真实机器。

完整记录应注明源码提交、测试命令、构建配置、证据摘要及产物哈希。P2P 抓包、外网 NAT 矩阵和 P1 尚未实现的测试单独列为待验收项。未经实际验证的结果保持待定。
