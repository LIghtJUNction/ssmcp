# SSMCP 0.10.30

本版本围绕长任务、主对话状态和实际任务可见性改进协作流程。发布资产、平台验收与精确源码身份以对应 GitHub Release 的清单和 Actions 收据为准。

## 主要变化

- **后台等待与结果缓存。** 调用窗口、后台观察期限和终态保留期分别计算。调用者断开后，服务端继续观察原任务；重连用原请求 ID 或等待 ID 恢复，处理后显式确认缓存结果。
- **独立等待面板。** 终端、Web 和桌面展示等待状态、耗时、结果读取延迟及确认状态，并对有界样本提供耗时统计。
- **定时提示词。** Agent 可以设置绝对或相对触发时间、重复间隔、模板和变量。事件单独标记为 `agent_timer`，按精确版本确认，保持用户输入和 Agent 提示词的来源区别。
- **主对话生命周期。** Agent 状态收口为 `working`、`idle`、`offline`、`dreaming` 和 `retiring`。空闲维护围绕清理、文档、检查及整理开展；收到新指令时恢复工作，状态事件可观察和等待。
- **会话总览与命令统计。** 总览区分已保存定义与当前连接，原生命令详情保留完整只读参数、真实退出状态、CPU、峰值内存及可用的磁盘跟踪结果。
- **连接恢复。** 稳定设备身份与每次连接身份分别记录；恢复保留原账号、授权和任务依据。未知结果需要核对原操作。
- **主对话自动订阅 worker 状态。** 已验证的主对话与关联 pool 绑定建立托管订阅；可在 CodeMode 中列出、配置及关闭。状态事件唤醒原等待，保留原任务与游标。
- **统一输入显示与引用回复。** 人类输入、系统提示、定时提示、worker 事件和维护提示使用右侧输入样式，并保留来源。按钮或快捷键将原消息 ID 与正文放入可编辑引用，保留已有草稿，经普通发送流程交付。
- **桌面多行输入。** Enter 换行，Ctrl+Enter 发送；引用回复支持 Ctrl+Shift+R。运行时跟踪记录保留在事件页，使共享对话集中显示实际消息。
- **原生回复与真实用户等待。** 必读指引要求通过 SSMCP 回复用户，并在回答后等待真实用户输入。
- **跨平台验收与发布来源。** Windows 验收加入真实桌面窗口证据；发布导出纳入已采用的 `zi18n` 与 `zhex`，分别核对 Git 锁定源码和独立 registry 版本。

## 使用入口

后台观察的创建、恢复、结果重读与 ACK 见[等待任务、协作对象与用户](await.md)。定时模板、事件版本与连接范围见[定时提示词](time-prompts.md)。worker 的任务 claim、完成回执和退休流程见[worker 协作](workers.md)。

等待与提示词都绑定原连接和真实 Agent 身份。已完成、失败、取消及未知是任务结果；它们与 Agent 当前处于哪一个生命周期状态分别记录。定时事件触发后，原生客户端可独立记录带来源的可见输入；同一 Agent 后续工具响应再领取提示正文，处理后按精确事件版本 ACK。可见记录、正文交付、ACK 和用户同意完成分别记录，任何一步都不替代其他步骤。

## 安装与验证

从本版本 Release 选择匹配系统与架构的附件，并核对 `SHA256SUMS`、`release-manifest.json` 和实际程序的 `--version`。安装、服务端部署与已运行客户端的重载分别记录；发布附件本身不会更换正在运行的进程。完整步骤见[版本发布与跨平台安装](releases.md)。
