# 账号门户、会话管理与安全审计

门户提供账户和公钥管理、个人会话、连接历史，以及仅管理员可见的用户、统计和拓扑。页面由服务器生成，使用同源表单，没有前端脚本或第三方字体。入口是服务首页；登录后点击“我的会话”或“历史记录”。

## 配置管理员与审计

管理员权限来自服务器配置中的 GitHub 数字 ID。推荐直接填写 `admin_github_ids`：数字 ID 在 GitHub 用户改名后保持稳定，不依赖浏览器提交的用户名或角色。

```toml
[portal]
gateway_socket = "/run/ssmcpd/management.sock"
audit_dir = "/var/lib/ssmcpd/audit"
admin_github_ids = ["123456"] # 替换为管理员的真实 GitHub 数字 ID
admin_github_users = []
audit_retention_days = 7
audit_max_events = 20000

# 仅在旧 SSH 账户确实属于该 GitHub 用户时显式绑定。
# 新自助账户 gh-<GitHub数字ID> 已自动确定归属。
owner_mappings = { legacy_ssh_user = "123456" }
```

也可使用 `admin_github_users = ["your-github-login"]`。网关启动时会向 GitHub 解析名单，再用数字 ID 校验权限；解析失败会拒绝启动。希望权限不随用户名重新分配发生变化时，使用数字 ID 配置。

管理员名单默认为空。配置权限、主账号映射、审计参数不符合要求时，服务拒绝启动。配置文件不得允许组或其他用户写入，属主须为 root 或服务用户；包含 OAuth secret 的配置仍须使用 `0600`，不要提交到仓库。

## 普通用户可以做什么

- 查看由自己 SSH 账户建立的在线会话，包括完整会话 ID、客户端名称、报告的主机和工作目录、连接时间，以及已授权的 GitHub 访问者。
- 在二次确认后断开自己的连接。
- 分页查看自己发起的账号操作、工具调用，以及自己拥有的会话的连接和调用事件。

会话所有权根据服务器验证的 SSH 账户确定：`gh-123456` 属于 GitHub ID `123456`；旧账户通过 `owner_mappings` 明确绑定。`/allow add 用户名` 允许其他账号控制当前会话，不授予门户中的会话管理权。

“断开会话”关闭当前工具连接。启用看门狗的客户端可能重新连接；持续停用需要在客户端本机停止服务，或撤销相应公钥并等待 SSH 同步生效。删除公钥不会关闭已经建立的连接。

## 管理员可以做什么

管理员可查看所有当前会话、在线 SSH 账户数、客户端报告的主机数和注册用户数，并查看“网关 → SSH 账户 → 会话”的连接拓扑。用户列表只包含 GitHub 用户名、数字 ID、SSH 用户名和公钥数量，不展示公钥正文或任何登录凭据。

管理员可断开会话、查看服务范围的安全审计。每个管理员查询和操作都重新验证登录身份和网关权限；隐藏导航只影响界面，不承担权限校验。

名称、主机名和工作目录是客户端提供的显示信息。权限判定使用 SSH 认证账户、GitHub 数字 ID 和服务器配置，不相信客户端自报的这些字段。

## 审计内容与保留期

日志记录账号登录、退出、公钥变更、访问拒绝、会话连接、断开、工具调用和管理员访问。时间戳与顺序 ID 由网关生成。工具调用记录经过 OAuth 验证的调用者和会话所有者；登录码或自动清理等没有 GitHub 调用者的路径不会编造身份。

审计只保存事件元数据，不保存令牌、密钥、公钥正文、命令正文、工具参数、执行结果或聊天内容。客户端名称、主机名、工具名、会话 ID 仍属于可识别的操作信息，只向有权的账号和管理员展示。

默认保留 7 天，最多 20,000 条；可配置 1–30 天、1–100,000 条。正式日志文件最大 16 MiB，达到数量或大小上限时提前清理最旧记录。启动、读取和写入时会清理过期数据，后台也每分钟清理一次，因此无人访问时仍会清理。

原子整理期间会短暂生成临时文件；重启会清理本模块遗留的临时副本。日志不是无限期归档，也不是不可篡改的外部证据系统：具有服务用户或服务器 root 权限的人能访问本地存储。

敏感变更和工具派发前先持久记录请求。若记录失败，拒绝执行；执行后记录完成结果。如果操作已完成但最终记录失败，请先检查实际状态，再决定是否重试。“已记录请求”表示存在请求证据，不能据此推断操作成功。自然断开和系统清理仍会继续，记录失败会写入服务错误日志。

门户发起的审计写入按匿名请求、已登录账号和全局总量分别设置限流预算，超限拒绝不会继续递归写日志，防止用大量失败请求挤占正常历史。

## 两个服务之间的安全边界

独立门户通过私有 Unix socket 向网关查询和操作会话。门户和网关须运行在同一个服务 UID 下。socket 使用 `0600`，两端均校验对端进程的用户 ID；管理协议不暴露到公共 HTTP 端口。浏览器不能自行提供操作者身份或管理员标记。

所有会话修改使用 POST，并继续验证登录 cookie、CSRF、同源 Origin 和允许的表单字段。普通用户查询由网关强制限制范围，直接更换会话 ID、查询参数或 URL 不会扩大权限。审计目录为 `0700`，文件为 `0600`，拒绝不安全的属主、链接和多个写进程。

## 部署方式

同进程部署可设置 `[portal] state_dir`，由网关同时提供门户。已有独立门户部署应在共享配置中省略 `state_dir`，通过门户服务的 `--portal-state-dir` 指定账户目录，并加上 `--portal-only`。门户进程只连接管理 socket，不重复打开审计写入器或 SSH 控制 socket。

独立门户的示例启动参数：

```text
ssmcpd serve --config /etc/ssmcpd/ssmcpd.toml --portal-only
  --listen 127.0.0.1:8086
  --portal-state-dir /var/lib/ssmcpd/portal
  --client-registry /var/lib/ssmcpd/portal-oauth-clients.toml
```

**账号 CLI、邀请和设备连接使用单进程标准部署**，迁移命令见[部署指南](deployment.md#标准账号部署与旧配置迁移)。下述双进程模式仅供旧 SSH 门户使用，不适用于账号 CLI。

双进程 Nginx 配置可参考 [`packaging/nginx-ssmcp-portal.conf.example`](../packaging/nginx-ssmcp-portal.conf.example)。它把首页、CSS、`/account/`、`/setup`、`/setup/` 和 `/api/setup/` 转发到门户；GitHub 回调按门户 state 前缀分流。配对页面和 API 必须进入同一个门户进程，否则无法共享短期配对状态。单进程部署继续使用原有 `nginx-ssmcp.conf.example`。

新增的会话管理入口都在现有 `/account/` 前缀下：

| 路径 | 用途 |
| --- | --- |
| `/account/sessions` | 当前账号的会话 |
| `/account/history` | 当前账号的审计与连接历史 |
| `/account/admin` | 管理员统计、拓扑、注册用户与会话 |
| `/account/admin/history` | 全部审计历史 |
| `POST /account/sessions/disconnect` | 通过 CSRF 和所有权校验后断开会话 |

首次部署此能力需要更新网关和门户。重启会使内存中的网页登录和 OAuth 授权失效，账号、公钥、客户端登记和审计数据保留。上线前应准备回退制品与配置，并验证重新连接和授权路径。历史记录从启用审计后开始；服务不会伪造此前未记录的历史。
