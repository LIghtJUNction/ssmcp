## 工具容器

连续的工具活动现在可以在一个有界容器中阅读。分组来自已验证的 CallScope：连接代次、会话线程和实际调用者的 provider/subject 都必须相同；已绑定的 agent 用其真实 ID，未绑定调用还必须属于同一个 run/request。两个相同的显示名称不会把活动合成同一组。

容器最多显示八行主体，展开的单个工具最多显示四行输出。鼠标在左半区域滚动时，先移动当前工具的输出，再移动工具组，到达边界后才移动整段对话；右半区域直接滚动主对话。方向键选择能够显露原本藏在组内的工具，Enter 保留折叠/展开行为，显式回到最新内容后恢复跟随输出。追加内容、裁剪旧预览以及切换列时，位置用事件 ID 保存，不用容易变化的行号冒充身份。

这些变化只组织保留的显示预览。原始工具记录、输出归档、状态和调用者信息继续由原有数据源保存，没有把工具原文复制成新的会话历史。

## 链接与选择

Activity 的对话正文和普通工具输出会识别 HTTP(S) 地址、Markdown 链接和 OSC8 链接。Markdown 显示名称和 OSC8 标签可以与真实目标不同；打开时使用对应的完整目标，长链接换行也不会只打开其中一段。裸网址去除句末标点，并保留成对的括号。

链接以下划线显示。一次左键按下和释放必须命中同一个可见单元格，等待 250 毫秒确认没有第二次点击后才调用系统打开器。拖动、滚轮、双击、切换复制模式、键盘输入、窗口尺寸变化和目标替换会取消待打开操作。后台追加信息时，如果锚定阅读区的目标没有改变，正常单击仍可完成。

F7 继续切换终端原生选择模式；支持 Shift 绕过应用鼠标的宿主也可以使用 Shift+拖动。打开器收到单独的 URL 参数，不经 shell 拼接。测试使用私有的记录型 xdg-open，既不打开用户浏览器，也不请求测试网址。

## Unicode 排版与控制字符

链接的点击区域必须与最后显示的文字使用同一套宽度。一个 emoji 可以由多个 Unicode 字符码点组成，例如家庭序列包含数个人物和连接符，但通常只占两个单元格。逐码点累加会使其后面的链接位置偏移。

修复前的固定输入已经产生可重复的错位：家庭 emoji 后的链接起点为 9、爱心为 2、带肤色的程序员为 7；对应的预期位置都是 3。旗帜案例原本就是 3。新的路径以完整 grapheme 为单位换行、补齐和生成点击区域，并保留原始字符序列；单元格太窄时用一个省略号表示放不下的整体，避免把组合体切成两半。

排版前仍执行原有文本安全处理。Markdown 中的 CSI 和 bidi 控制以字面形式展示；OSC8 只进入有界目标表，其他控制字符串不形成可点击的隐藏载荷。最终帧只输出允许的样式控制。VT 解析器负责解释 SGR 样式，不再用逐码点的屏幕模型重新排版 emoji。

## 资源与平台边界

每份缓存最多有 64 个目标、32 KiB 目标文本；单个目标最多 2048 个 UTF-8 字节。源范围最多 128 个，自动扫描最多 256 KiB，可见命中项最多 1024 个。软换行保存短 ID，完整 URI 在目标表中只保存一份。原有预览仍受 128 个事件、总计 2 MiB 文本限制。

系统打开器最多并发四个，进程由自有回收线程等待结束，不累积无界任务。实现提供 Linux、Windows 和 macOS 的现有系统打开命令；本轮真实 PTY 验收范围是 Linux。诊断原始 VT 日志、差异渲染和任意宿主的字体显示不在“全部支持链接”的承诺范围内。
