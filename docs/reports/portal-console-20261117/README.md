## 已上线的能力

门户采用暗色背景、克制的绿色强调色、等宽命令区域和响应式排版。普通用户登录后可查看并断开自己的在线会话，检查自己的账号操作、连接与工具调用历史。管理员可查看服务统计、完整会话 ID、连接拓扑、注册用户摘要，以及服务范围的审计记录。

管理员由服务器配置指定。生产已使用 LIghtJUNction 的稳定 GitHub 数字 ID 配置权限；支持的字段、用户名解析方式和旧 SSH 账户映射详见配置文档。权限在服务端验证，不依赖浏览器传入的角色或用户标记。

审计保留 7 天、最多 20,000 条；正式日志文件另有 16 MiB 上限，后台每分钟清理。记录事件元数据，不记录密钥、令牌、命令正文、工具参数、执行结果或聊天内容。敏感变更与工具派发前先持久记录请求，无法写入时拒绝执行。

首次上线在 Nginx 重载后立即检查配对接口时收到 503，部署流程自动回滚。第二次上线加入新 worker 就绪检查，并只对短暂的 `temporarily_unavailable` 响应做有限重试。实际等待新 worker 258 ms，配对接口首次返回 200，没有使用 503 重试。

第二次上线的外层传输在 14:06:43 UTC 先记录了 `remote_receipt_unavailable`；服务器独立部署任务在 14:07:02 UTC 才完成并写出成功回执。之后只读恢复了原始回执，并核对两个服务的实际执行文件。报告恢复没有重新部署或再次重启服务。本目录的 `deployment.json` 以该服务端真实回执为准，早期传输失败记录仍可在 Git 历史中追溯。

## 使用边界

历史从启用审计后开始；此前未记录的历史无法补造。“断开会话”关闭当前连接，启用看门狗的客户端可能重新连接；持续停用需在客户端停止服务，或撤销公钥并等待 SSH 同步生效。删除公钥不会立即关闭已建立连接。

审计存储具有访问权限、单写入者和容量保护，但服务器 root 或服务账户仍能访问本地文件。当前实现不提供外部不可篡改日志存储。
