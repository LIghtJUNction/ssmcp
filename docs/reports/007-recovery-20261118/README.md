## 为什么能够保持轻量

常驻进程只维持一条出站 WSS 连接、处理服务器保活和五个管理操作：status、list、wake、close、remove。空闲路径跳过完整 Runtime、PTY、工具发现和模型 harness；需要创建或管理会话时才启动短暂的管理命令。

每个正式会话有自己的 systemd 用户单元和程序快照。正常客户端升级改变日常安装入口，007 继续运行保存的恢复副本；旧正式会话继续使用创建时的快照。通过新名字启动并验证新版会话后，可以关闭旧会话。若日常客户端损坏，可用新名字加 `recovery: true` 唤醒恢复副本。

已有名字再次 wake 时复用原定义，包括原程序版本；`recovery: true` 不会替换已有会话的程序。工作目录限定在安装时指定的根目录内，最多保存 16 个会话。实现位置为 [zero.rs](../../../src/client/zero.rs) 和 [install.rs](../../../src/client/zero/install.rs)。

33 项故障验收使用 loopback 假服务器、合成账号凭据和独立临时 systemd 单元，覆盖以下实际故障路径：

- 连接关闭、超大帧和连接静默后的重连；拒绝认证后退避，并在本机修复凭据后重新读取。
- 状态缓存无法写入时，仍能恢复连接并响应管理请求。
- 禁止一般命令执行、任意启动参数、目录越界和逃逸根目录的符号链接。
- 同名重复 wake 保持正式会话 PID 与服务器连接；close 保留定义；remove 停止并删除活动会话。
- 正式会话使用独立 cgroup；停止、重启 007 后，正式会话进程、连接和进行中的命令保持运行。
- 日常安装入口损坏后，007 仍可管理；恢复副本可启动可用的正式会话，已有会话也能从原快照恢复。
- 空闲及管理操作结束后没有常驻子进程。

## 连接连续性的范围

007 提供独立的恢复入口，支持升级时让新旧正式会话并存交接。它不会把断开的 TCP 连接变成原连接，也不能让主机断电时的进程继续运行。网络恢复后会重新注册并获得新的 client ID；正式会话的网络断线、显式 restart 和主机重启仍遵循普通 ssmcp 的任务生命周期。

完成注册后，75 秒没有有效入站消息会触发重连；连接建立和等待注册完成分别有 30 秒超时。网络重试使用带抖动的指数退避，最长 60 秒；进程退出后由 systemd 每 15 秒尝试恢复。凭据失效时保留授权边界，在本机修复账号后自动重新读取。

复现命令、安装参数、五个工具的参数与停用方式见 [完整使用说明](../../007.md)。
