## 2. 目标模型与实现原则

“进程”对应逻辑会话 session，“线程”对应该会话内具有独立身份的 agent。两个 ID 是路由和隔离的标识，不要求为每个 agent 创建操作系统进程或线程。消息只有在身份和会话归属验证通过后，才能进入对应线程的等待区。

上下文隔离需要落实到每个数据入口。只在面板上显示不同线程 ID 不足以避免串线；用户消息、自动注入的历史、记忆、触发器提示与确认记录，都必须沿同一个 session_id／thread_id 作用域读取和写入。共享信息需要显式选择 session 或 workspace 范围。

广播分为两种：会话内的 /global 发给该会话当前的各线程；命令行 --global 面向调用者有权限访问的全部在线会话。广播进入等待区，不强行覆盖 agent 正在处理的上下文。重复请求使用幂等键去重，容量不足必须给出失败回执。

## 6. 必须先解决的集成问题

### 6.1 触发器提示 ID 类型

自动化原生接口返回正整数 id，同时用 next_cursor／acked_cursor 表示队列进度。根分支的初版提示汇总器曾把 id 当作字符串读取，会丢弃真实提示；字符串测试夹具掩盖了这个问题。

修复目标是接受 JavaScript 安全整数范围内的正整数 ID，保留数字类型，携带 source_scope，按游标确认已经处理的消息。输出预算耗尽时应停止，不能先跳过早期提示又交付后续游标，避免确认时误删尚未看到的内容。修复命令曾发出但完成状态未知，恢复后必须检查并用真实原生返回值测试。

### 6.2 webhook 出入站字段兼容

出站载荷包含 schema_version、id、event、text、data 和 created_at_ms。初版入站结构使用 deny_unknown_fields，但未接收 created_at_ms，因此自身出站载荷投向自身入站接口会失败。

应明确统一载荷结构，允许需要的时间字段，并验证权限仍来自账户凭据和授权会话，不来自请求体中的身份信息。还需检查所有目标均排队失败时的 HTTP 状态，避免发送端把失败回执当作成功交付。

### 6.3 Runtime 注册与线程作用域接线

webhook 模块还需要 Runtime 和 registry 的 Provider 注册、构造与分发。线程范围能力还需要将 client 的 Frame::Call 中的 session_id／thread_id 传给 Runtime::perform_in_thread；元数据分支提供了该入口。

作用域必须在进入异步或阻塞任务前正确捕获。不得在绑定线程的调用里退回到无标识的工作区上下文，否则会重新引入串线。

### 6.4 历史检索与确认记录

[PR #45](https://github.com/LIghtJUNction/ssmcp/pull/45) 的远端头为 9101a832ced45b0772ffa1bf0269ebeb999c6062。它提供工作区范围的历史元数据和搜索，可以复用；本轮要求的默认线程范围还需要索引和授权语义。

线程后续提交依赖 context_memory::record_thread_delivered_request。用户消息确认记录和 assistant 记录需要连接到线程范围索引。不要把 webhook 通知写入“用户要求”，也不要把同工作区其他线程的历史默认注入当前线程。

### 6.5 原生启动和 UI 合并

可选 harness 的既有实现位于 [017e404](https://github.com/LIghtJUNction/ssmcp/commit/017e40425352390d80932f66114f9aa747af7001)，包含 lazy backend 和启动测试，当前没有进入主分支。本轮应整合必要变更，保持外部 harness 按需加载。

现代网站及帧边界工作已经存在于主分支历史，合并时应保留。UI 工作树需要重新确认页面注册表、按键冲突、配置持久化和 Agents 分组，再检查窄屏实际渲染；不能只依据数据结构测试宣布“全面美化完成”。

## 7. 待集成接口规格

下面是候选实现的调用形式，用于接续开发，**不表示已部署可用**。最终应以注册工具的实际 schema 为准。

### 消息命令行

~~~sh
ssmcp send --thread THREAD_ID --session SESSION_ID "请检查当前改动"
ssmcp send --session SESSION_ID "同一会话的所有 agent 请同步进度"
ssmcp send --global "全部授权会话的所有 agent 请保存检查点"
~~~

入口包括 GET /api/client/threads、POST /api/client/messages 和 POST /api/client/webhooks。身份校验和在线状态检查完成后，才允许写等待队列。回执需要区分 queued、重复投递和 failures。

### 原生记忆与触发器

~~~js
await memory.write(clientId, {
  name: "decisions.md",
  content: "# Decisions\n消息按线程投递。\n",
  create_only: true
});

const saved = await memory.read(clientId, { name: "decisions.md" });
await memory.search(clientId, { query: "线程", limit: 20, offset: 0 });
await metadata.paths(clientId, {});

await triggers.put(clientId, {
  trigger: {
    id: "review_failures",
    event: "tool_error",
    prompt: "再次尝试前检查 {tool} 的失败原因",
    tool_prefix: "ssmcp.exec.",
    threshold: 2,
    cooldown_ms: 60000,
    max_fires: 8
  }
});

const pending = await triggers.poll(clientId, {});
// 只有本次返回的全部提示均处理完成，才确认 next_cursor。
// 部分处理时，只确认连续已处理提示的最后一个 ID。
await triggers.ack(clientId, { through: pending.next_cursor });
~~~

默认记忆范围取自经过验证的线程绑定。显式共享使用 scope: "session" 或 scope: "workspace"。更新时使用 read 返回的 revision 作为 if_match，避免多个写入者静默覆盖。记忆保留 Markdown 内容，方便未来独立的“做梦”整理机制读取；本轮没有启动或实现自动做梦任务。

触发器事件包括 project_enter、before_tool、after_tool、tool_error、before_answer 和 timer。提示属于 advisory reminder，不应提升为用户指令。timer 在工具边界或主动 poll 时检查；本轮实现不是后台主动运行模型的调度器。

### 动态页面

候选 ssmcp.ui.pages 支持 list、open、add、remove、reorder、rename。每页具有 id、title、view。页面数量由注册表决定，排序使用全部页面 ID 的显式列表，配置支持持久化。

默认先打开对话页，下一页为日志。输入框为空或处于浏览状态时左右方向键切页；输入内容时保留光标移动；Alt 加方向键用于明确切页。日志页面保留日志密度，对话页面使用更简洁的排版。
