## 本轮功能

- **直接使用独立 Zuse CLI 操作桌面与浏览器。** SSMCP 只提供版本查询、下载、安装、卸载四项管理工具。旧 `/computer`、on/off/toggle/status 兼容入口和默认 `Super + Alt + C` 已移除，内嵌执行器与旧 worker 不再保留。
- **明确显示等待状态。** 真正等待用户输入时显示红色符号、文字和剩余 `mm:ss` 倒计时。结束本轮须取得绑定当前请求、调用方的有效 Human 决策；普通文本、超时或取消不充当结束许可。
- **展开命令读取详情。** 保留主分支的 `exec.read` 改动，可在当前读取卡片展开这一批 stdout／stderr；两路文本与元数据共用 128 KiB 本地预览上限，超限保留首尾并标明截断。该显示副本经过终端控制序列清理和既有脱敏，不修改原工具返回，也不代表完整作业日志。

上述行为已经固定源码静态核对；实际客户端画面与交互仍按候选产品验证单独记录。本报告组没有操作正在直播的机器。

## 为什么保留两份源码归属

[`28054f3`](https://github.com/LIghtJUNction/ssmcp/commit/28054f3dad16152c46f7a886a677e2e4100d5c7c) 在移除兼容层后合入了主分支的命令详情展开功能。随后全目标检查发现服务端入口仍引用已退役的 `ssmcp::computer::worker_entry()`，因此该轮 Linux Clippy 以 101 退出。

`83b5bc5` 只从 `src/server_main.rs` 删除这段 7 行旧入口，没有改动库、依赖、gitlink 或六份发布配方。原生核对确认新选出的库测试程序仍为 **159877648 字节**，SHA-256 为 `7f42250748f6bf392beee6b04da7f636484a76c29a51f8d93d5d8cbe2377bf2f`，Cargo 标记为 fresh。因此保留 `28054f3` 的实际库执行记录，并以字节一致和源码差分说明其与 `83b5bc5` 的关联，明确 **没有再次执行这组库测试**。修复后的 Clippy 和集成检查则确实在 `83b5bc5` 上执行。

更早 `c56c040` 的两项编译错误、`1358f84` 的一次工具摘要探测失败均保留在历史记录。后续定向及完整回归通过，不等于已经证明旧探测失败的根因。详见[前次编译阶段记录](current-iteration-CLI-compile-retry.md)。
