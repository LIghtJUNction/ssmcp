## CI 支持版本号调整

[版本号工作流](https://github.com/LIghtJUNction/ssmcp/blob/4f73f5684279ecae1a8e8486e4332c20bdbaab95/.github/workflows/bump.yml) 支持 `none`、`patch`、`minor`、`major` 和 `custom`，默认使用当前版本。另有 `dry_run` 预览与 `publish` 选择。`none` 可以准备标签并发布当前版本，不表示完全没有写入。

[准备与触发逻辑](https://github.com/LIghtJUNction/ssmcp/blob/4f73f5684279ecae1a8e8486e4332c20bdbaab95/scripts/bump_release.py) 从工作流最初的 `github.sha` 计算版本。重复运行复用同一版本提交与标签，不从新的 main 再递增；只允许正常快进，并拒绝移动已指向其他提交的同名标签。

Release 请求显式包含标签、`build_only=false`、`deploy_server=false`。同一 Bump run 的后续 attempt 在 POST 前拒绝自动重发；首次请求失败或响应不确定时保留原始请求与 HTTP 输出。这是 helper 层的单次调用约束，不是网络端的恰好一次保证。新增 12 个测试定义已进入实际通过的 118 项发布脚本检查；dispatch 部分使用模拟响应，尚无真实 Bump Actions 发布成绩。
