## 本轮对使用者的改进

[PR #159](https://github.com/LIghtJUNction/ssmcp/pull/159) 汇集了本轮累计改动。消息的输入方式与最终处理者分别记录：前者决定文字从终端、管道等哪里进入，后者决定消息送给谁。这样，关闭人类聊天输入的客户端仍可提供执行与原生通讯。

|---|---|---|

| 文件引用不可用 | 保留原文发送，并提示引用不可用 | U 中 5 项引用回归通过；消息引用界面组、管道、MCP 与 socket 路径完成实际验证 |

## 新发布核验器：把请求、构建与公开文件连接起来

[独立公开目录](https://github.com/LIghtJUNction/ssmcp/tree/2257fb1d235bba59e8a0d1747a4f4afc6348bad3/docs/reports/command-await-delivery-20261120/publication-verifier-manual-main-unbound) 已包含三份代码、完整差异、使用说明、capture schema、两份准备记录和独立静态审阅，共九个文件。三份代码只完成语法与独立静态审阅，**尚未运行核验器**；最终 S、P、run 和原始 dispatch 回执仍为 **UNBOUND**。

核验器已经实现两条检查链：

1. 原始 dispatch 命令、输入和 HTTP 返回值，与独立执行回执共同绑定唯一的原始运行。
2. 固定运行中的 job 日志、源码检出、Actions artifact ZIP、包内文件和公开 Release 文件逐层对应。

旧核心合同继续保留：19 个精确 job、18 success 与 deployment skipped、16 个发行资产、四个 gitlink、完整源码文件集合，以及官方 crate 和两类依赖图。Windows sidecar 按生产端的 CRLF 处理，Unix 按 LF 处理。具体检查规则及信任范围见[使用说明](publication-verifier-manual-main-unbound/README.md)。

九份公开文件的新增或变更部分均已逐字读回，旧 v25 核验器原字节保留。正式使用时还需绑定实际运行，并取得完整日志、有效 artifact 和公开产物。
