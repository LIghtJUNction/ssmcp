# 公共前端独立进程：本地验收记录

## 已验证的结果

公开指南和已知静态资源现在可交给独立的 Linux `ssmcp-frontend` 进程。核心继续处理 OAuth、账户状态、访问控制、流量账本和设备连接。本地验收实际停止第一个前端进程并启动第二个；同一核心中的设备 WebSocket、会话对象和原 OAuth AT 保持有效，授权快照字节未改变。此结果限于下面固定的源码和私有测试环境，没有安装或重启真实服务。[实现](../../../src/portal/frontend.rs) · [真实替换用例](../../../src/portal/frontend/tests.rs) · [部署边界](../../public-frontend.md)

这组测试在一个持续运行的测试进程内启动生产 HTTP router，另行启动两个真实 `ssmcp-frontend` ELF。`ssmcpd` ELF 也完成构建与实际 `--help` / `--version` 验收；这里不把测试进程描述成独立运行的 `ssmcpd` 服务。核心自身重启时的授权恢复由前一阶段的[OAuth 持久化记录](../oauth-grants-20261119/README.md)覆盖，核心重启仍会关闭既有网络连接。

专项用例验证：

- 非公开操作、未知字段和任意文件名被拒绝。
- 非私有目录、符号链接、非 socket 文件和第二个写入者被拒绝。
- 私有 socket 正常传输页面和 PNG，取消服务后清理自有端点。
- 超时、超大响应、错误协议、错误内容类型及错误哈希均触发回退。
- 新前端的资产哈希可使用；旧核心页面的旧哈希仍对应旧内置字节；不存在的哈希返回 404。
- HTTP Cookie、Authorization 和不可信 Host 不进入前端请求。
- 更换真实前端进程前后，原授权和同一设备连接继续可用。

验收过程中先有一次为紧急输入法修复让出编译窗口的主动中断；随后首轮编译发现 `Portal::open` 的显式构造遗漏新增可选字段。补为 `frontend: None` 后重新执行上述完整门禁。两次前缀日志保留，均未作为通过的测试计数。

## 运行边界

这是公开内容的进程拆分。动态账户页面、OAuth、账户写入和计费仍在核心。首次配置 `[portal] frontend_socket` 需要让核心加载新设置；这一次核心维护仍会中断连接。后续只更新公开指南和静态资源时，可单独替换页面进程。[配置与失败行为](../../public-frontend.md)

核心与前端使用同一服务 UID，并校验真实 Unix peer credentials。私有目录和 socket 分别为 `0700` / `0600`，路径逐级 no-follow 打开，端点退出清理核对 inode；这是受信服务组件的边界，不是任意第三方插件沙箱。Linux `/proc/self/fd` 用于保持目录描述符锚定。[端点实现](../../../src/portal/frontend/socket.rs)

核心最多同时等待 16 个渲染请求，每个总超时 250 毫秒；worker 最多 16 条活动连接，每条 2 秒，正文上限 2 MiB。失败使用内置内容，且不会把不匹配的字节放到已有哈希 URL 下。本次没有公网反向代理或 systemd 实机部署验收，也没有声称整个 Portal 或任意扩展都已独立更新。

另一位协作者只读复核了 renderer、socket、guide 和 assets 接线，未发现有证据的阻断；实际运行结果来自本记录的门禁，不将只读复核计为执行测试。
