# 007 恢复连接升级验收

2026-11-20 · Asia/Taipei · Linux 实机

## 结论

007 恢复连接已由 0.7.4 升级为官方 0.10.13，实际运行协议为 wire v7，连接状态恢复为 connected。升级后，两个独立 code_mode 回合分别调用 `ssmcp.007.status` 和 `ssmcp.007.list`，四次原生调用均成功，两个回合保持同一个恢复进程和同一个连接。原始回执的脱敏汇总见 [evidence.json](evidence.json)。

本次只更新 `ssmcp-007.service` 的独立恢复映像。日常 CLI 仍为 0.10.12，其文件内容和 inode 均保持不变；升级前记录的 11 条活跃客户端连接、进程启动身份及运行映像全部保留。007 保存的 10 份会话定义与程序快照、恢复配置和 unit 定义也保持不变。

## 实机步骤与回执

升级前的读取确认了旧程序仍在运行，但连接在 connecting / reconnecting 间重试。直接从进程映像读取的版本为 0.7.4；它的 SHA-256 与此前记录的 wire v5 映像一致。旧程序没有写入运行协议字段，因此“旧协议”依据是映像对应关系，不能表述成现场直接读到了 wire v5。升级后的 wire v7 则由新进程状态和真实 MCP 响应直接返回。

内置 `007 upgrade --dry-run --json` 成功核对了实际加载的 unit、恢复映像与候选来源。正式 `007 upgrade --json` 返回 exit 0 和 `success: true`，报告新的 PID、候选 SHA-256 和本次操作后的 connected 观察。该命令使用其既有的备份、原子替换及连接确认流程；实现见固定发布提交的 [upgrade.rs](https://github.com/LIghtJUNction/ssmcp/blob/4e3132d60600dca5053af81cdefa6962c3058ac4/src/client/zero/install/upgrade.rs)。

两个后续 MCP 回合验证了连接能够继续处理请求。第一回合的恢复进程运行时长为 26 秒，第二回合为 32 秒；每回合的 status 均返回 0.10.13 / wire v7，list 均返回 10 份保存会话。两次回合之间没有重新选择连接来替代原连接，结束后的本机状态仍为 connected。

## 保存状态与回滚材料

前后快照验证了原有状态的保留，而不只依赖升级命令中的声明。会话定义和独立程序快照按内容计算摘要；配置和 unit 按原文件内容计算摘要；活跃进程按 PID、启动时间和运行映像摘要逐一比较。下表的每项结果均已写入 evidence.json。

旧恢复映像的独立备份仍在本机，文件权限为 0700，摘要与升级前一致。本次升级成功，没有执行现场回滚，因此这里只确认备份存在、内容正确且独立于新映像，不宣称实际回滚已经演练。
