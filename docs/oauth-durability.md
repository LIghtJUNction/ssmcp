# OAuth 账户授权跨重启恢复

配置 `[oauth] client_registry` 后，核心进程会同时保存客户端注册信息和账户授权。有效的访问令牌、正常刷新的刷新令牌，以及已经生效的撤销状态可以跨正常重启恢复；到期时间不会因为重启重新计算。该功能解决过去“注册信息还在，但 AT/RT 对应授权已经丢失”的问题。[授权实现](../src/oauth.rs) · [持久层](../src/oauth/grants.rs)

这不保存网络连接。重启核心仍会关闭它持有的 WebSocket 和进行中的请求；客户端需要重新连接。授权持久化也不能找回升级前已丢失的内存状态。公共前端独立替换属于另一层进程边界，不能把令牌恢复等同于连接不中断。

## 配置与文件

沿用已有配置，不需要第二个账户数据库：

```toml
[oauth]
client_registry = "/var/lib/ssmcpd/oauth-clients.toml"
```

该目录必须为服务账户拥有的 `0700` 目录，祖先不能经过符号链接；状态文件为 `0600`，拒绝多硬链接和竞争写进程。systemd 的 `StateDirectory` 默认路径仍适用；没有配置路径且没有该环境时仍使用内存模式，启动日志会说明。[目录与锁校验](../src/oauth/registry.rs) · [启动配置](../src/server_main.rs)

| 文件 | 内容 |
| --- | --- |
| `oauth-clients.toml` | DCR 客户端元数据、客户端密钥摘要、原登记期限 |
| `oauth-clients.toml.grants.json` | 账户授权族、AT/RT/已兑换授权码的 SHA-256 哈希、固定期限、客户端和资源绑定 |
| `oauth-clients.toml.grants.json.pending` | 未完成持久提交的意图；正常提交完成后不存在 |
| 原注册表锁文件 | 两类文件共用的单写进程锁 |

授权文件不包含可直接使用的 AT、RT 或授权码明文。账户 subject、提供者、显示名、resource 和已登记的回调地址仍是私有元数据，因此备份需保持相同权限和 issuer。快照最大 64 MiB，并受现有授权族、令牌和代码数量上限约束；它不会无限追加日志。[记录类型与上限](../src/oauth/grants.rs)

只恢复账户身份授权。尚未完成的网页登录事务、尚未兑换的一次性授权码，以及依赖某一条旧连接的 Legacy 授权不会恢复。已兑换授权码的哈希只作为重放检测记录，不能再用来产生新的授权。

## 提交顺序与故障行为

普通鉴权不写文件。签发、刷新和撤销修改状态后，服务先完成持久提交，再返回相应结果：

1. 生成有大小上限的快照，记录绝对到期时间。
2. 创建私有 `.pending` 意图文件并同步文件与目录。
3. 将完整快照写入同目录临时文件，同步文件，原子替换目标，再同步目录。
4. 删除意图文件并同步目录，随后返回令牌或已完成的撤销结果。

若意图文件已成功建立而后续替换失败，当前进程拒绝继续使用不确定的授权状态；下次启动发现意图文件也会拒绝自动接受旧快照。不要直接删除标记后把旧授权当成有效状态，应先核对私有文件和失败原因。[提交实现](../src/oauth/grants.rs)

若磁盘故障发生在持久意图尚未建立之前，操作返回 HTTP 503，本次不签发凭据；当前进程同样拒绝继续鉴权。但此前已经成功保存的状态仍可能在修复磁盘并重启后恢复，失败的撤销不能宣称已经生效。管理员手工恢复整套旧备份也不属于本机制能够检测的回滚。封禁仍由核心的账户策略独立检查；管理操作不会把 OAuth 撤销存储失败报告为成功。[管理撤销](../src/broker/management.rs)

## 有效期与重放

访问令牌、闲置期限和授权族总期限均保留原来的壁钟截止时间；运行时同时检查单调时钟。刷新可以按原规则延长闲置期限，但不能越过最初的总期限和客户端登记期限。恢复时过滤已过期授权，拒绝 issuer 不匹配、损坏记录、重复键、孤立令牌和来自未来时间的快照。

已使用的刷新令牌哈希保留到该授权族原来的总期限。使用旧 RT 重放会撤销该族并保存撤销结果。授权码重放仍先核对客户端、resource、回调和 PKCE；错误的绑定不能被用来撤销他人的授权。一个账户或授权族的撤销不应影响另一账户的有效授权。[旋转与鉴权](../src/oauth.rs)

## 同站点授权迁移

原地升级只需保留原持久目录、配置和 issuer，不需要先导出再导入。`ssmcpd oauth` 提供的是独立的授权迁移入口：它只迁移 MCP OAuth 客户端登记和账户授权，不包含门户账户、CLI 设备登录、计费数据、服务配置或网络连接。[迁移实现](../src/oauth/transfer.rs)

在维护窗口停止持有源注册表的核心进程后，以状态文件所属的服务账户运行。导出会取得同一独占锁；仍有写进程、未完成提交标记、损坏文件或不安全权限时拒绝继续，不会绕过检查。

```sh
sudo -u ssmcpd ssmcpd oauth export \
  --public-url https://ssmcp.example \
  --client-registry /var/lib/ssmcpd/oauth-clients.toml \
  --output /var/lib/ssmcpd/oauth-export-new

sudo -u ssmcpd ssmcpd oauth import \
  --public-url https://ssmcp.example \
  --input /var/lib/ssmcpd/oauth-export-new \
  --output /var/lib/ssmcpd/oauth-restored-new
```

所有路径必须是绝对路径，输出目录必须不存在。命令在新建的 `0700` 临时目录中写入 `0600` 状态文件，复用现有持久层验证，并核对带摘要的 `migration.json`。整目录完成后才通过禁止覆盖的原子重命名发布；已有目标即使为空也不会被替换。返回的 JSON 只给出路径、数量、摘要和覆盖范围，不打印令牌或私有授权记录。

导入只接受相同 issuer，并保留原客户端期限、授权族总期限、刷新重放记录和已用授权码。命令不自动修改配置或启动服务；将回包的 `client_registry` 路径显式配置到新核心，并继续保留原门户状态与身份提供者配置。跨机器搬运导出目录时应维持私有权限，以目标服务账户读取；命令不会自动 `chown` 或用 root 身份绕过所有权。

若源目录只有客户端登记、没有账户授权文件，回包会明确标记 `coverage: "client_registrations_only"`。这不能证明旧访问令牌已保全，也不能恢复已经丢失的内存授权。完整账户授权快照标记为 `account_grants`，但仍不迁移未完成登录或 Legacy 连接授权。旧备份不能代表备份之后的刷新、撤销或新授权；应使用停写后取得的当前快照，不能把恢复旧快照当成安全的授权回滚。

后端升级仍可能中断 WebSocket 和正在执行的请求。现有客户端会用保存的账户凭据自动重连，网络故障不会清除登录；已过期、已撤销或身份不匹配的凭据仍须重新授权。这项迁移不保证第三方 MCP 客户端保持原网络连接，也不会重放执行结果不确定的业务请求。

## 本地回归

```sh
cargo test --locked --offline --lib oauth:: -- --test-threads=2
cargo test --locked --offline --lib broker::management -- --test-threads=2
cargo clippy --locked --offline --all-targets -- -D warnings
```

新增回归覆盖：账户 AT/RT 恢复与原总期限、RT 重放跨再次重启、授权码 PKCE/resource 绑定、显式账户撤销、过期记录清理、损坏或未完成提交、权限与符号链接，以及意图建立后替换失败时拒绝旧快照。[持久化测试](../src/oauth/grant_tests.rs)

真实进程回归启动三个私有测试进程，使用生产 HTTP router 和临时账户存储：第一个进程接受原 AT 并旋转 RT；第二个接受旋转后的 AT、拒绝旧 RT 重放；第三个确认该族仍已撤销。每一代子进程均由测试持有并等待退出，监听仅在 loopback，目录在结束时清理。它验证真实进程退出后的文件恢复，没有连接 GitHub OAuth、操作真实账户或重启已安装服务。
