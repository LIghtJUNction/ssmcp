# Linux 任务资源保护

Linux 客户端在启动任务前建立 cgroup v2 限额。来自同一系统用户的多个 SSMCP 会话共用总预算。每个会话有自己的额度，普通管道命令和 PTY 命令的子进程计入所属任务。额度按内核报告的物理内存和可用 CPU 容量计算。

| 范围 | 默认内存上限 | 默认 CPU 时间配额 | Swap 上限 |
| --- | --- | --- | --- |
| 同一用户的 SSMCP 会话合计 | 物理内存的 1/2 | 可用 CPU 的 75% | 0 |
| 一个会话及其子进程 | 物理内存的 1/4 | 可用 CPU 的 50% | 0 |
| 一个命令及其子进程 | 取物理内存的 1/8 与所属执行单元有效内存上限的 1/2 中较小值 | 与同会话的其他命令共用会话配额 | 0 |

例如，系统报告 16 GiB 物理内存和 8 个可用逻辑 CPU 时，总内存预算为 8 GiB，单会话为 4 GiB，单命令为 2 GiB。所有会话合计最多使用相当于 6 个 CPU 的运行时间，一个会话最多使用 4 个。多个任务同时运行时也受共同的上级限制。

当任务达到自己的硬限额且内核无法回收足够内存时，内核终止该任务组。原任务回执通过 `memory_limit_exceeded` 和 `memory_limit_bytes` 给出判定依据，内核支持时另有 `memory_peak_bytes`。若进程因致命信号退出，回执保留实际退出信号。例如，`SIGILL` 表示该进程最终因非法指令信号终止，要查明此前发生了什么仍需查看其错误输出或崩溃报告。

已绑定的发起者可在后续调用中收到 `system_hook` 提示。内存提示给出任务 ID 和阈值，提醒缩小批次、减少并发或流式读取数据。崩溃提示给出最终信号。处理提示后可以按任务 ID 确认，查询原任务仍能看到退出结果。

这些 Linux 限额需要可访问的 systemd 用户管理器和已委派的 cgroup v2 控制器。客户端先核对内核实际生效的限额；无法建立受限执行环境时，启动会返回错误。更新磁盘上的客户端后，重新启动或重载会话才能使用新逻辑。
