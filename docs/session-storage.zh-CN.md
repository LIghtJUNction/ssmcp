# 保存会话的磁盘准入限制

保存会话会保留启动配置、独立执行映像和生命周期日志。创建一个新会话时，管理器先在已有的 `manage.lock` 内检查容量，再复制当前程序并原子提交新目录。达到上限会拒绝这次新建，不会为腾空间删除旧配置、映像或正在运行的会话。

## 两个创建上限

| 项目 | 边界 |
| --- | --- |
| 保存目录数量 | 最多 1024 个；已提交的 `session-*` 目录与中断后留下的 `.prepare-*` 目录都占名额。 |
| 保存的执行映像 | 上述目录内的映像合计最多 4 GiB，即 4,294,967,296 字节。按文件的逻辑长度计算，不按文件系统压缩、稀疏或共享块估算。 |

这两个值是当前实现的固定上限。扫描只读取目录和映像元数据，不重新读取或计算所有旧映像的哈希。已有的私有目录、普通文件和链接检查仍然适用。

复制前先检查当前程序的长度是否放得下；复制过程中继续扣减剩余预算，因此源文件在复制时增长也不能绕过限制。准备失败时，只清理这一次创建的临时目录。两个创建进程竞争最后一个名额时，持有同一管理锁顺序检查和提交，不能各自看到同一个空位并同时越界。

进程异常退出可能留下 `.prepare-*`。残留的目录与映像继续计入预算，不会因缺少最终 manifest 而被忽略，也不会在下一次启动时自动删除。确认它不再被创建操作使用后，可按自己的归档策略处理。

## 已有记录如何继续管理

准入检查只作用于新建。已保存的会话不会因为总映像超过 4 GiB 而被终止或禁止按名查看、启动、停止和删除；本次改动也不主动迁移它们。达到上限时，可先用已有管理命令确认不再需要的会话，再显式删除：

```sh
ssmcp sessions list --json
ssmcp sessions status NAME --json
ssmcp sessions remove NAME
```

`remove` 会停止并删除所指定的会话，执行前应确认名称。这里没有后台清理或按最近访问时间淘汰会话的机制。

旧版本已有的枚举保护保持不变：无分页的 `sessions list` 和服务端保存记录枚举最多读取 1024 个已提交定义。如果旧目录本来就超过该数量，枚举仍会明确报错；按已知名称管理仍可使用。容量准入不会把这个既有错误静默变成截断列表。

## 预算覆盖范围

4 GiB 只约束保存的执行映像，不是整个用户目录的物理占用保证。生命周期日志沿用 256 KiB 轮转阈值，保留当前及上一份；单个状态文档沿用 128 KiB 限制。终端输出、对话历史、检查点与附件分别遵守自己的存储合同，未被复制进这个快照预算。

每个保存会话继续使用自己的不可变程序快照，以便安装更新后仍能按原配置恢复。此次没有增加共享映像目录、硬链接去重或后台迁移，也没有复制历史或附件。磁盘实际剩余空间不足时，底层文件操作仍可能提前失败。

实现见 [`src/session/storage.rs`](../src/session/storage.rs) 与 [`src/session.rs`](../src/session.rs)。相关入口和管理语义见[常驻会话服务](session-service.md)；历史及检查点的独立上限见[主动恢复索引](session-recovery.zh-CN.md)。
