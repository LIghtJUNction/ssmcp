# SSMCP 0.10.21

## 终端与消息

- **直接阅读实际命令。** 相邻命令各自显示 argv、运行状态与 shell 语法颜色，默认预览最后三行输出。长内联脚本保持紧凑标题，详情中保留脱敏源码、执行目的和已记录输出，并支持独立滚动。超出预览上限时提示截断与 `/command` 入口；查看历史不会重新执行命令。 [命令显示验证](reports/readable-commands-20261120/validation.json)
- **原生消息与组发。** 在获准的设备账户收件箱和已验证线程之间双向发送文本。单发使用精确地址，组发只发送给显式选中的 1–32 个收件人，并分别显示回执。回执记录入队、放入工具响应和确认收取等阶段，任务执行情况由收件方另行报告。 [原生消息指南](thread-messaging.md)
- **按所选收件人使用 `/send`。** 命令沿用最近一次明确选择的组、原生收件人或本地目标。原生消息发送原文，本地监听仍准备文件和技能引用。组发部分成功时保留草稿，重试沿用原组及各目标的请求 ID。 [发送与回执](force-send-listener.md)
- **在 `/send` 正文中补全引用。** 支持 `@file` 和 `$skill` 候选，保留 Unicode 与缩进；引用候选列表打开时，第一次 Enter 或 Tab 接受候选，之后的 Enter 才发送。收件人和群组路由保持各自的解析边界。 [引用补全验证](reports/send-reference-completion-20261120/README.md)
- **引用与草稿取回。** 普通要求中的缺失 `@file` 或未知 `$skill` 会提示引用不可用，符合大小限制的正文仍可发送。空输入框按 ↑ 可取回仍待交付的要求，确认后移除对应的待交付记录。跨连接恢复去向未确认的要求时，原尝试保留，另起一份待编辑的请求。 [引用和队列](client-ui.md#输入要求与队列)
- **身份与历史描述。** 界面区分操作系统 PID、中继连接 ID 和逻辑线程 ID。在线角色短摘要上限为 128 个 UTF-8 字节。本地历史标题与摘要可以单独保存，分别最多 256 和 2048 个 UTF-8 字节。 [成员身份](client-ui.md#agent-面板与成员身份) · [历史描述](client-ui.md#本地历史标题与摘要)
- **历史与审计。** 对话按所选历史显示带归属的任务输出和原生回复，Logs 与 Tasks 保留跨会话审计。晚到的回复可写回仍可写的原会话，`/copy` 继续使用所选历史的回复。 [本地消息与历史归属](client-ui.md#本地消息与回答问题)

## 等待与完成

公共 `await` 与 JavaScript `waitFor` 可等待执行任务、relay 任务、协作成员状态、自己的协作收件、用户输入和已有结束审批请求。普通目标支持任一满足或全部满足；用户输入与结束批准使用独立事务。每次等待最多 25 秒，超时可以用同一 wait ID 恢复。取消只停止观察，不终止任务、确认消息或批准结束。公共 `await` 不占用 JavaScript 执行槽；在 code mode 内使用 `waitFor` 仍占用所在的执行槽。 [接口与验证边界](validation/await-finish-20261120.md)

结束许可要求真人明确选择 Yes，且匹配当前请求、成员和线程。agent 的 Yes、普通 ready / done 或超时都不能产生许可；许可只能消费一次。该约束适用于 SSMCP 的完成接口，不能拦截完全停止调用 SSMCP 的宿主自行输出外部 final。

## 依赖与运行版本

`zharness` 升级至 0.6.0，带入 `zcall 0.4.0` 和 `zguard 0.1.0`。每轮迭代及发布前核对实际使用的 Project Z 包，采用最新未撤回稳定版并固定版本、源码与锁文件。`zuse-computer 0.2.2 → zmcpio 0.4.0` 仍按已发布上游约束保留 `zcall =0.3.0`，等待兼容的正式上游版本。 [依赖版本与维护规则](dependencies.md)

连接 0.10.13 旧中继时，可用 `--account-compat` 和该中继已验证的自身账号注册连接。原生消息另需客户端与中继支持，`messages.*` helper 也须由中继提供。 [账号兼容说明](client-accounts.md) · [能力要求](thread-messaging.md#兼容范围)

公共 `await` / `waitFor` 需要更新后的中继，被动结束观察需要支持相应操作的客户端。Release 工作流保留 0.10.21 的部署延后规则：发布安装包不会自动重启现有生产 relay，也不会让活动客户端自动加载新版本。
