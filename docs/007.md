# 007：轻量常驻恢复连接

007 在 Linux 后台维持一个小型、已认证的唤醒通道。需要工作时，它才启动完整 ssmcp 会话；平时不初始化终端、浏览器、文件工具或模型 harness。正式客户端更新、退出或启动失败时，007 仍可用于恢复连接。

恢复连接使用当前网关要求的传输协议版本（当前为 v7），但工具范围仍只有下文列出的五项会话恢复能力。它会验证并接受工具调用后的 `CodeModeFinished` 观察帧，以保持连接兼容；这不会启动完整 Runtime、终端界面或模型。被唤醒的完整会话有自己的连接、能力与消息队列。协议版本决定两端如何交换消息，工具目录决定这条连接实际允许做什么。实现见[恢复连接](../src/client/zero.rs)和[传输协议](../src/wire.rs)。

## 安装与查看

先用普通 ssmcp 完成账号授权，再以同一个普通用户安装：

```sh
ssmcp 007 install --cwd "$HOME/Documents/GITHUB" --client "$(command -v ssmcp)"
ssmcp 007 status
```

`--cwd` 是允许新会话使用的工作区根目录。`--client` 指向日常升级的完整客户端；省略时使用执行安装的程序路径。`--server` 可选择已经登录的服务器，`--name` 可设置远程列表中的名字，默认名字是 `007`。

安装会启用并启动 `ssmcp-007.service` 用户服务。配置、已知可用程序副本和私有会话默认位于 `~/.local/share/ssmcp/007`，目录权限为 0700，配置权限为 0600。`SSMCP_007_HOME` 可以指定另一个绝对路径。

```sh
# 只查看安装计划
ssmcp 007 install --dry-run

# 本机管理
ssmcp 007 stop
ssmcp 007 start
ssmcp 007 status --json
systemctl --user status ssmcp-007
journalctl --user -u ssmcp-007

# 检查退出登录后及开机时是否保留用户服务
loginctl show-user "$USER" --property=Linger
```

要在无人登录时启动并在登出后持续运行，用户管理器需要启用 linger。系统提供 `loginctl enable-linger "$USER"`；安装结果会报告当前 linger 状态。相关行为见 [loginctl 官方文档](https://www.freedesktop.org/software/systemd/man/latest/loginctl.html)。

`status` 分别返回 systemd 服务状态和 `connection_state`。进程存活时，连接可能处于 `connecting`、`connected` 或 `reconnecting`。因此 `ActiveState=active` 只证明进程在运行，不能证明网关已经接受它。观测缓存只在 PID 与当前服务匹配时使用；缓存不可用显示 `unknown`，不影响恢复连接。

`versions` 同时显示执行此命令的 CLI 版本 `command`、保存副本的版本 `saved`，以及匹配当前 PID 的最近观察中的 `running` / `running_wire`。旧程序没有写入这些新字段时，它们可以为空，不能据此猜测运行版本。`connection_observation` 包含观察时间、状态和可用的最近错误；错误经过审计脱敏、控制字符过滤和长度限制。

## 唤醒正式会话

在 MCP 的 `list` 中选择 007 的 client ID，通过已有 `code_mode` 调用：

```javascript
await call(recoveryClientId, "ssmcp.007.wake", {
  name: "repair",
  cwd: "ssmcp"
});
```

这里的 `ssmcp` 是安装时工作区根目录下的子目录。省略 `cwd` 使用根目录。返回的 `connection_state` 为 `connected` 后，再通过公开 `list` 选择正式会话的 client ID。创建成功与连接上线分别报告。

| 工具 | 作用 |
| --- | --- |
| `ssmcp.007.status` | 查看恢复连接、工作区、程序路径与资源边界 |
| `ssmcp.007.list` | 列出这个 007 管理的正式会话及连接状态 |
| `ssmcp.007.wake` | 创建正式会话，或恢复同名已保存会话 |
| `ssmcp.007.close` | 停止指定正式会话，保留定义 |
| `ssmcp.007.remove` | 停止并删除指定正式会话 |

所有远程参数都有固定 schema。新会话继承同一个服务器和本机账号，工作目录必须位于安装时指定的根目录。007 不接受远程传入命令、程序路径、身份或任意启动参数。

同名、同目录的重复唤醒复用原会话；运行中的会话保持原 PID 和连接。已关闭会话会重新启动。相同名字换目录会被拒绝。每个 007 最多保存 16 个会话，显式 remove 可释放定义。

本机可以管理同一组私有会话：

```sh
ssmcp 007 sessions list
ssmcp 007 sessions status repair
ssmcp 007 sessions close repair
ssmcp 007 sessions start repair
ssmcp 007 sessions restart repair
ssmcp 007 sessions remove repair
```

## 显式升级恢复程序

007 保存独立的程序副本。普通客户端更新会改变 `--client` 指向的安装入口，007 自己继续从保存的副本运行；重复 `install` 也会保留现有副本。这能保留恢复入口，但意味着副本不会自动跟进服务器的协议要求。旧副本可能一直运行，却因注册被拒绝而反复重连。

先准备包含 `upgrade` 命令的新版日常 CLI，再使用同一个普通用户执行：

```sh
# 验证本次 CLI 与已有安装的关系；不重启服务或替换程序
ssmcp 007 upgrade --dry-run --json

# 更新这一个恢复服务，并等待新的连接证据
ssmcp 007 upgrade --json
ssmcp 007 status --json
```

升级使用本次 CLI 实际正在运行的程序映像。它不在升级途中选择另一个下载版本，也不重新安装或修改保存的会话。流程如下：

1. 锁定这份安装，核对配置、受管理的 unit 内容、systemd 实际加载的 `FragmentPath`，以及当前进程的程序映像。其他安装、额外 drop-in、待 `daemon-reload` 的状态或无法确认的运行进程会使升级拒绝继续。
2. 在私有状态目录保存独立的 `ssmcp.backup-…` 旧程序，并暂存当前 CLI。报告给出备份路径和 SHA-256；备份在成功或回滚后都保留。
3. 重新核对安装归属，仅停止 `ssmcp-007.service`，原子替换恢复程序并重新启动该 unit。
4. 最多等待 65 秒，要求出现不同于旧进程的 MainPID、与新映像相同的文件身份，以及同一 PID 在本次操作后写入的 `connected` 观察。单纯 `active`、旧缓存或旧 PID 都不能通过。
5. 激活失败或收到可处理的中断时尝试恢复旧程序。若 unit 或映像已被其他操作改变，则保留备份并报告错误，不覆盖该变化。

成功结果包含 `success: true`、新 PID 和连接状态。失败返回非零退出码，并在 JSON 中分别记录 `rollback.binary_restored`、`service_started` 和 `connected`。**恢复了旧文件不等于恢复了网络连接**：如果旧程序本来就不兼容当前网关，回滚后仍可能重连失败。应保留失败报告和备份，检查版本、账号授权与网络状态；不要把回滚字段中的某一项成功解释为全部恢复。

升级保留 007 配置中的 `client`、工作区与服务器，保留 unit 定义，也保留所有既有正式会话的定义、独立程序快照及 systemd unit。它不会更新或重启这些正式会话。安装、启停、卸载与升级通过本安装的管理锁串行处理。

自定义 `SSMCP_007_HOME` 或 `XDG_CONFIG_HOME` 只会改变 CLI 查找的文件路径，不会创建另一套用户 systemd 管理器。升级始终核对管理器真正加载的安装；仅有另一目录中的同名文件不能授权它停止当前服务。升级的实现与验证边界见[升级模块](../src/client/zero/install/upgrade.rs)。

## 紧急恢复与正式会话版本

新建正式会话默认使用配置的正常安装入口；升级 007 本身不会修改这个路径。

如果新版完整客户端启动失败，可另起一个名字，使用保存的恢复程序：

```javascript
await call(recoveryClientId, "ssmcp.007.wake", {
  name: "repair-known-good",
  recovery: true
});
```

`recovery: true` 只在创建新名字时选择恢复程序；若名字已经存在，仍复用该会话原有快照，不会切换版本。

已保存会话保持创建时的独立程序快照，restart 或重复 wake 都保留该版本。需要新版时创建新名字，接入并验证后再关闭旧会话。返回 `reused: true`、`executable_preserved: true` 表示复用了原定义。

007 与每个正式会话分属独立 systemd unit/cgroup。关闭或重启 007 不结束正式会话；正式客户端更新也不重启 007。systemd 会按单位清理所属进程，因此采用独立单位维持生命周期隔离，详见 [systemd.kill](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html)。

网络中断后会重新登记连接，并获得新的 client ID。已有正式会话继续遵循普通 ssmcp 的断线和重载语义；显式 restart、会话自身网络断线或主机重启会改变其连接与任务生命周期。007 提供持续的恢复入口，并支持新旧正式会话并存交接。

## 空闲开销与恢复策略

007 使用单进程事件循环，直接建立一条出站 WSS 连接。它不运行完整 Runtime，不建立 PTY，也不周期扫描工具、项目或会话。需要会话操作时才运行短暂的管理命令。

当前服务器每 25 秒发送 WebSocket ping；007 仅回复 pong。完成注册后，连续 75 秒没有有效入站消息时重连；建立连接及等待注册完成分别有 30 秒超时。网络错误使用带抖动的指数退避，最长 60 秒；进程崩溃由 systemd 每 15 秒尝试恢复。关闭 systemd 启动限流，避免持续故障耗尽重启次数后永久停用，参见 [systemd.unit](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html)。

消息与单帧上限是 64 KiB，读取缓冲区是 4 KiB，最多同时执行一个管理请求；管理命令输出上限是 32 KiB，超时是 40 秒。会话列表返回精简字段，长路径和诊断文本不会撑大常驻进程。状态缓存写失败只提示一次，恢复连接继续工作。

认证复用已有账号和 TLS 信任校验。每次重新连接都重读凭据；本机更新授权后可自动恢复。凭据过期或撤销时继续退避，保持已有授权边界。

资源测量与故障测试见 [验收报告](reports/007-recovery-20261118/README.md)。CPU 时间、RSS/PSS 与 TCP 计数均从运行进程采样；它们用于描述资源成本，报告不推算整机瓦数。

## 停用与卸载

```sh
ssmcp 007 stop
ssmcp 007 uninstall
```

stop 停止恢复连接，已启动的正式会话继续运行。uninstall 停用并移除本安装所属的 unit，保留恢复程序、配置和会话。已经保存的程序副本不会被普通安装或卸载覆盖，方便故障后再次启动或检查。只有显式 `upgrade` 会按上述验证与备份流程替换恢复副本。

## 复现验证

```sh
cargo build --release --bin ssmcp

python3 scripts/e2e_007.py \
  --binary "$PWD/target/release/ssmcp" \
  --native-systemd --idle-timeout \
  --report /tmp/ssmcp-007-e2e.json

python3 scripts/benchmark_007.py \
  --pid "$(systemctl --user show ssmcp-007 -p MainPID --value)" \
  --seconds 300 --interval 1 \
  --output /tmp/ssmcp-007-benchmark.json
```

故障测试使用 loopback 假服务器、临时目录和合成凭据。其 native 模式会创建独立临时 systemd 用户会话并清理它们。资源脚本只读取目标 PID，记录 RSS、PSS、CPU 时间、线程、文件描述符、子进程与 TCP payload 字节；TCP/IP 包头和纯 ACK 不在该网络计数内。

### 隔离升级事务

升级事务有独立的验证入口：

```sh
python3 scripts/e2e_007_upgrade.py \
  --binary "$PWD/target/release/ssmcp" \
  --report /tmp/ssmcp-007-upgrade-e2e.json
```

这个夹具使用私有的 systemctl 替身和合成账号网关，启动真实的 007 与正式会话进程。它验证备份、原子替换、新 PID 连接确认、激活失败后的回滚，以及正式会话和在途任务的保留；另一个安装目录不能让它停止当前加载的安装。真实 systemctl / systemd-run 被阻断，现有用户服务和账号不参与测试。

夹具把同一个候选程序复制为原副本与升级副本，报告明确记录 `same_binary_baseline: true`。这证明升级事务及生命周期行为；旧版本到新版本的实际上线结果需要另行记录。原有 `e2e_007.py` 还可接收 `--fixture-binary`，指向同一候选源码构建的库测试执行文件，以验证真实 Broker/HTTP 路由上两次调用仍使用原恢复连接。
